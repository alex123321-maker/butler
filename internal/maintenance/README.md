# Independent release admission

Work in progress for issue21. This package compares complete submitted source
inventories and conservatively classifies changes against fixed operator
module boundaries. It deploys nothing, creates no maintenance grant and accepts
no author's passing verdict as authority. Unknown paths, protected boundaries,
links and submodules require protected-kernel treatment. Digest ordering is
canonical; case aliases and unsafe/ambiguous inventories are rejected.
Actual source/build measurement must come from the independent checker.

Signed independent review evidence pins both built artifacts, the complete source
diff, operator profile, checker, fixed and hidden corpora, criteria, schema,
protocol and runtime identities. Every required regression, hidden, compatibility
and functional check retains baseline/candidate outcomes and measured cost;
unavailable evidence, regression or unapproved unknown usage denies admission.
The checker signing key must stay outside author code and its trial environment.
A verified review grants no maintenance authority or deployment on its own.

Migration105 and `Store` retain immutable profiles, staged inventory bindings,
signed positive/negative reports and audit events. Profile installation starts
stopped; reconfiguration increments the stop epoch and invalidates observation.
The private owner Stop path does not depend on Core. Resume requires a fresh
actual node observation and cannot erase uncertainty. SQL guards prevent
rewriting terminal UNKNOWN, refunding a consumed permission or erasing history.

Signed node identity observations bind the profile, owner/target, exact nonce and
stop epoch. History retains missing/unknown artifacts and configuration mismatches.
Only a fresh current response can update the qualified identity; stop/resume and
reconfiguration invalidate it. Nonce replay cannot overwrite newer evidence.
This authenticates an inspector's report, not the actual inspector implementation:
the node process and fixed-target physical inspection still require acceptance.

The [maintenance contract](../../docs/architecture/maintenance-contract.md) remains
proposed. Controller service, independent checker, node execution, effect admission,
state compatibility and actual process/rollback acceptance are still required.
No production profile is enabled by this package.
