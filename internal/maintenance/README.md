# Independent release admission

A private Linux `capsuleGuardHost` can now create a fixed128MiB/32PID/one-CPU
guard container, verify actual cold files/configuration and strictly never-
started state, then measure the trusted guard's real PID/start time, namespaces,
UID/GID/capabilities/seccomp, cgroup/no-swap, read-only mounts, environment and
descriptor boundaries. It publishes no marker and executes no candidate. Cold
owned-object cleanup is separate from qualified running-runtime inspection;
the latter remains strict. Lifecycle operations serialize, terminal faults stay
terminal, and the original five-second close context includes lock acquisition.
Seven Linux/race tests and six subcases pass with vet0. Earlier failures and
independent findings are preserved in the [guard host evidence](../../experiments/maintenance21/2026-10-26/guard-host-v1/README.md).
This private preparation/measurement component is not a launch authority,
functional checker or release acceptance. Its constructors are not model tools.

The optional `GuardedPackager` now packages one privately pinned static Linux
guard and independently built candidate with fixed `/maintenance-guard`
entrypoint, UID/GID and modes. It clones the trusted guard, validates its actual
ELF/hash and verifies both imported files through a never-started disposable
container. Cleanup failure denies the package result. The legacy direct-entry
recipe remains distinct and unchanged. Actual local Docker/race checks pass
both recipes and the strict archive checks, with vet0 and no skips. This is
artifact evidence only: it executes no candidate and grants no review or
deployment permission. The later fixed executor must independently verify the
guard, kernel bounds, live authority and launch barrier.

The optional private `NodeControlClient`/handler carries exact signed records
across the separate node/controller boundary. Dispatch repeats the Store's live
one-use checks; outcome recording retains the original signed measurement.
The fixed operator owner/target and separate node token cannot be replaced by
request data. Node authentication grants no owner controls, claim creation,

requires an additional private token distinct from the owner token. A lost reply
is not retried. Actual process-boundary tests and a physical executor are still
required; this component is not release acceptance.

The private controller can register canonical separately signed owner permission
and revoke it independently of Core. A nonce is unique across the target's whole
history; exact retry retains its original allowance and revocation. Registration
does not consume a claim or dispatch. Stop epochs, current profile, independent
checks, physical identity and finite consumption must still be verified at each
future action. Protected scopes require an existing exact qualifying review.
A rollback requires its own measured reverse stage/report and fresh explicit
permission; an old forward report is insufficient. Actual retained-artifact,
compatibility and rollback execution gates remain pending.

The controller-side Store can reserve a signed exact pending effect claim while
atomically consuming permission and advancing the target fence. Identical retries
return the original receipt. A different operation cannot bypass an unresolved
effect. The node's separate one-use `AdmitDispatch` rechecks current profile,
epoch, base/observation, review validity and owner revocation before returning;
signed bytes alone are insufficient. No transaction spans a physical operation.
Owner stop cancels only pending claims, without refund. Already dispatched work
remains unresolved until measured evidence arrives. Deadline expiry records
UNKNOWN without replay; a late signed measurement is retained separately and
cannot rewrite that terminal attempt or clear uncertainty without reconciliation.
Signed node outcomes preserve newer owner stops and map only the exact known
base or independently reviewed candidate. These are storage/admission components;
there is no deployment endpoint, actual node executor or live compatibility gate
yet, and no enabled deployment profile. The separate optional local
`apps/maintenance-controller` exposes only private independent owner controls;
its separate owner process is exercised with Core absent: wrong/ambiguous
requests are denied, an enabled synthetic target is stopped, and its newer stop
epoch survives a controller process restart. This is not node/deployment proof.

The private `SourceSnapshotter` materializes all blobs of an exact existing Git
commit, including tests/configuration and export-ignored files, into a separate
checker workspace outside the author repository. It preserves content/mode
inventory, excludes dirty/untracked checkout data, rejects moving refs/tree-only
objects/links/submodules/case aliases, and executes no submitted source. Owned

A private `DockerBuilder` and fixed scratch-ELF packager now pass actual isolated
component validation. The builder copies the complete rechecked
snapshot into an owned volume, invokes only a pinned operator Go compiler with
network/module downloads disabled, and measures the actual ELF and imported
Docker image. Author tests, generation commands and Dockerfiles are retained in
the inventory but never selected as build instructions. Compilation does not run
the resulting program. The first compiler supports dependency-free Go capsules;
unavailable dependencies fail. The actual private daemon test compiles a capsule,
captures its static ELF and measures the imported image ID. Fixed/hidden release
checking, trial and deployment acceptance remain pending.

Before compilation the builder also reads actual Linux cgroup v2 limits
and the exact worker process identity. Memory/CPU/PID, UID/capability/new-privilege
and IPv4 route checks fail closed. Swap must have an actual zero limit at the
container or an ancestor; an ignored Docker option is insufficient. This initial
profile requires host PID visibility and cgroupfs; unsupported visibility/layout
fails before source compilation. These kernel checks pass against the actual
private worker. A fixed trusted PID1 supervisor waits for a private marker until
the host verifies bounds, then invokes only the fixed compiler. The host pins
that measured process's `/out` tmpfs with `os.Root`; no author-selected host path
is accepted. Completion is published by atomic rename. Initial Docker exec/copy
API failures remain retained; no capabilities or bounds were loosened.

one-shot process pass a separate actual-process observation test. Only nonce/epoch/exact-profile

The read-only `DockerInspector` pins one private local Unix socket and literal
container target. It reads Docker's actual immutable image ID, full Config
(except the separately measured image reference), HostConfig, mounts and actual
network membership. Only opaque configuration identity and physical state leave
the inspector; raw environment/configuration and daemon errors never do. Tags,
labels and health text do not establish artifact identity or functional success.
Missing targets are explicit; ambiguous JSON/state, redirect, cancellation and
unavailable daemon observations fail closed. It performs no writes, signing,
effect settlement or UNKNOWN reconciliation. Public tests use a real local Unix
HTTP listener with synthetic Docker responses. A separate opt-in Linux/race test
also measures the exact stopped fixture in a private Docker28.3.3 daemon; it is
actual image/configuration proof, not functional/trial/promotion acceptance.
The fixture separately passes actual kernel checks for UID65532,64MiB memory,
one CPU,32 PIDs, no capabilities/new privileges/network routes or host key/socket
mounts. A private ancestor cgroup prohibits swap (the Docker driver cannot set
the per-container swap limit on this host). The original pivot-root and swap
probe failures remain preserved. Node effect execution/deployment acceptance is pending.
