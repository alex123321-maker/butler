# Communication control

The private immutable owner profile also bounds outstanding owner questions:
`MaxOpenInteractions` is zero/default16 or1..64. It is not a model argument,
content permission or mutable UI setting. Invalid bounds reject the profile;
the owning publication transaction enforces the ceiling across sessions.

Fixed credential-free message/photo/report/widget schemas and strict decoding.
Recipients, owner, task identity, admission mode and grants are kernel-owned.
V1 widgets always block; false wait is rejected before persistence. An accepted
receipt proves a durable publication only. This package registers nothing and
enables no transport or user profile. Photo/report contracts are foundations;
readiness must reject them until their representations and artifact checks exist.

The fixed private client refuses remote plain HTTP. HTTPS is required except for
literal loopback addresses and `http://orchestrator:8080/internal/communication`.
Proxy use and redirects are disabled; the service token cannot choose authority.

The version1 [fixture corpus](testdata/README.md) freezes four model formats,
three typed question kinds and a separately authored native Rich Message shape.
It is a C01 contract, not C06 rendering/live-delivery acceptance.
