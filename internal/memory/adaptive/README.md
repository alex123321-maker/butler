# Bounded adaptive retrieval (#87)

This prospective consumer is separate from memory authority and remains
unqualified/default off. A transparent code policy chooses no optional lookup,
literal identifier lookup, a reported-event-time filter, existing semantic/hybrid
retrieval or a bounded comparison/join. It adds no model or classifier dependency.

The intent gate never removes current task/constraints, transcript/summary,
working state or current scoped owner-confirmed preferences. These existing
necessary reads remain separately observable; no optional retrieval does not
mean zero PostgreSQL work. Every query/read still requires the actual Tool
Broker dispatch, current scope/grant/task/goal/input/lease and catalog ancestry.

Plans and call/open receipts are metadata only and cannot grant access. Finite
call/search/response/deadline counters survive process reconstruction. Found
snippets are discovery, not opened citations. A final evidence envelope binds
each quoted claim to an actual current `open`/`neighbors` range; source and task
guards repeat before release. This is explicit evidence structure, never hidden
chain of thought, a fact acceptance or proof of answer correctness.

Reported `EventTime` is not historical validity. The prospective filter uses UTC
`event_from <= EventTime < event_until`; unknown-time records cannot satisfy it.
Yearless/ambiguous periods require clarification instead of silently inferring a
year. #88 separately owns valid-time/known-time history and freshness semantics.

The policy and evaluation protocol are being implemented; this README is not a
passing production/native quality or cost receipt. Activation on main remains
separate #92 work. Independent quality/cost comparison and the applicable #83
lifecycle gate must pass before reviewed code can qualify this consumer.
