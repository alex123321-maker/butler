# Generated pure converters

The developer-return lifecycle guard first checks captured returned-package
provenance. Unrelated retained publications can be read/delivered without a live
worker lease. Actual returned-package pins still require the existing owned
snapshot and complete source/role/return checks; this does not grant execution
authority to a completed run or weaken Catalog/export revocation.

This Go module owns the single finite delimited-to-JSON IR, strict package/need
validation, fixed independent checker and Broker-owned PG lifecycle. Creation,
testing, trials, activation/rollback and use require ordinary exact action grants,
current task/owner authority, deletion-aware source graph and existing budgets.
Bodies remain Catalog DATA; metadata/history contains only hashes and SourceRefs.
Tool observations use the Broker privacy boundary's decoded-object JSON ordering.
Discovery and child-check receipt proofs reconstruct that exact representation;
typed struct field order cannot stand in for the actual journal result digest.

The separate developer/checker runtime has no network, core storage or account
access. `RoutedExecutor` delegates other contracts through `Next`.
`CheckPinnedLifecycleTx` composes after current source/authority guards at provider,
Broker and atomic-result boundaries, without RPC or another pooled connection.
ConverterPermission is separate from reviewed extension permission.
