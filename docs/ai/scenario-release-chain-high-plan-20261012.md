# Prospective native High release-chain protocol

This is a separately declared prospective experiment, not native acceptance.
Execution is closed while `chainHighReviewedPrerequisiteSHA` is empty. The new
bridge file must be independently reviewed and hash-frozen only after actual V2
quality and comparison PASS with complete observed cost and all252 new attempts.
It must carry the immutable228-call history into an actual480-call baseline. No
old report, counter, scope or native marker is reopened or rewritten.

The proposed new window is
`issue33-high-release-chain-20261012-baseline480`, with at most40 new provider
entries and total ceiling520. The deterministic reference complete workflow has
17 entries, so two complete workflows and Stop before child inference are
expected to use approximately36; additional entries consume the same40 slots.
The source does not promise native success within that ceiling, extend it after
failure, reset it per role/task/case, or retry failed entries.

The actual fixture has three cases:

- `restart_sent`: three real Broker project observations promote the original
  Task; native root/child tools perform development, independent test/trial,
  activation, original CSV conversion and readiness-patch preparation/check.
  Broker is SIGKILLed at actual child admission and restarted with the same
  tested binary/configuration/endpoint. Current independent owner completion
  then produces one persisted semantic notice and one loopback acceptance.
- `lost_ack`: a separate full native workflow uses actual recipient acceptance,
  an ACK-persistence fault, dispatcher reconstruction and natural claim expiry.
  It retains the same notice identity as `delivery_unknown`, without resending
  or running the original work again.
- `owner_stop`: the actual admitted child owns a live model-running Run/lease
  but waits before its first provider release. Current owner Stop invalidates
  that original tree; repeated owner delivery retains the same receipt. Old
  child read proof and actual Broker preparation are denied; worker drain checks
  no live old lease, no child action/success notice/final and retained confirmed
  parent effects. This tests a live Butler child before inference; it does not
  claim cancellation of an already running High server inference.

The original goal and owner criteria require `prepared_verified`: the exact
original CSV result and a checked immutable `ready=true` README patch. The
original project remains unapplied. Neither model prose nor a child report can
verify or complete that Task. Models propose ordinary Broker tools; fixture fault
observers read actual Task/delegation/run rows. The fixture supplies no scripted
native final, tool result, receipt or successful objective verdict.

All root/child Start, Continue and Submit entries share one fixed qualified
fixture PostgreSQL schema. Individual Task fixtures retain their own schemas;
that isolation cannot reset the shared counter. Admission uses the current
caller-owned transaction for exact root/child lineage, owner/session, live lease,
Task/delegation versions/deadline and source/grant checks, the shared counter CAS,
then fresh checks after any counter wait. Preflight denial costs zero native
entries. A committed provider entry remains spent if validation/auth/HTTP/stream
fails. Production budget reservations remain authoritative and are not refunded.

The prospective scope has a45-minute immutable deadline, each fixture at most20
minutes, each request at most120 seconds and finite tool deadlines. Antigravity
High's generation ceiling is32768 including thinking; the conservative input
quote is1048576. The owner-selected child allowance has four model turns with
four full input/output quotes, rather than the small scripted token allowance.
Models cannot widen these limits. Known High totals additionally bound generation
conservatively as `max(visible_output, total - prompt_input)`; stored visible
input/output pairs and old NULL history stay unchanged. This is not an invoice or
exact attribution of generic cached/thinking dimensions.

`scenario-release-chain-high-lab.sh prepare` compiles exact app/Broker/converter/
extension/TLS binaries and executes synthetic real-PG counter/current-proof tests
without importing credentials or contacting a provider. `execute` first checks
the independently frozen prerequisite using the prepared binary with network
disabled. Only then may fixed-host daily endpoint TLS-only checks and private
credential-file metadata checks run. A new fixed global marker is created once;
source/runtime bytes are compared again before its single atomic native start.
There is no resume, fallback or old-window mutation path. The converter remains
network-none and the actual Telegram adapter targets a loopback fake recipient.

Content-free request evidence preserves ordinal, scenario, entry kind, root/run
IDs, parent/child classification, input hash, admission/finish times, owning entry
elapsed milliseconds, outcome, allowlisted failure stage/code, observed
input/output/complete total and native version. A failed terminal retains uniquely
validated complete measurements; absent, conflicting or incomplete observations
remain NULL. A real zero input/output/total triple remains known zero; a legacy
nonzero pair with missing zero total retains that pair with NULL total. Tools and
final text require the complete total and exact version before release. Final
text additionally waits for a successful terminal event, so a contradictory or
unfinished stream does not publish it; already streamed deltas are not rewound.
Unknown full cost/version or failed owning checks produce failure;
they never become zero cost, model correctness or release permission. Runtime
auth, prompts, tool bodies and hidden reasoning are excluded from the safe scope
report. The runner also exports an independent allowlisted PostgreSQL request
witness before cleanup and content-free Docker start/finish/exit/OOM state.
