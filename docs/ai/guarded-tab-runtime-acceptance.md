# Optional guarded tab runtime acceptance — 2026-10-11

This change composes the actual Tool Broker application bootstrap with the
guarded status/click resource store. It defaults disabled. Orchestrator's separate
operator-only readiness projection gates scoped discovery and direct prepare.
Broker independently proves immutable selection/resource/budget schema, the
current private deletion anchor, exact native contract/host readiness and fixed
literal-loopback runtime/HTTP/gRPC routes. Its registry must omit legacy
`single_tab.*`; canonical guarded contracts and the local owning request are
registered explicitly. Current origin policy is checked on the actual selection
again at admission and runtime release. Local request dispatch remains outside
the browser executor lease, while preserving its exact journal and shared budget.

The new bootstrap proof uses actual `App.New/Run`, all65 migrations on a disposable
PG17 database, private HTTP/gRPC and source/deletion checks. Nine incomplete setups
deny: wrong host/token, LAN target, legacy registry, missing origin policy/request,
wildcard authority/Broker listeners and invalid deletion anchor. Scoped discovery
and direct prepare check the current owning runtime flag. An actual selected tab
executes through prepared intent, grant, permanent claim, shared budget, resource
ticket, private runtime authority and runtime receipt. A selected forbidden origin
stops before the backend; the proof requires exactly one backend call, one resource
dispatch and one budget reservation. Owner selection/revocation uses the actual
PG library; the private owning projection is read from PG for execution.
Extension metadata/observation are scripted in this bootstrap fixture, and no
actual model or human channel is involved.

The separate installed native host/extension/Chromium proof executes the canonical
contract and authenticated readiness, rejects a replacement host and covers ten
cases: valid click, manual input, fresh observation after manual input, DOM mutation,
navigation, foreign origin/host, lost ACK plus cold browser restart, two executors
and actual Linux native manifest launch. Local click ACK remains an unknown
external effect; synthetic recipient call counters do not establish human recipient
success. The two-executor fixture now waits for the actual held action instead of
an incidental total native RPC count, which readiness legitimately increases.

## Remaining activation gates

This is a tested optional route, with its main deployment flag still disabled.
Direct Linux loopback is the proved topology; remote aliases/gateways, Windows
private-file ACLs and the actual owner-channel activation remain separate gates.
Origin policy does not intercept a user's page networking or switch its account.
Uncertain lanes have no automatic or unproved owner reconciliation. Workspace,
shared-memory conflict and shared local model production adapters remain separate
work for issue17. The sealed native model window and issue16 quality verdicts are
unchanged; this proof makes zero actual inference calls.
