## Fixed native design

Maximum80 new Start/Continue/Submit entries across every root/child/scenario and
one durable shared schema `fixture_chain_v5_high`. The ceiling is derived from
the actual frozen baseline plus80. Global expiry comes from one runner-created
absolute60-minute timestamp; case contexts have20minutes and each admitted
entry has the earliest SQL-admission+120seconds/global/current-parent deadline.
Restart and schema reconstruction cannot refill the counter or extend expiry.
High model/version,131072 input bytes, conservative1048576 input-token quote,
32768 generation ceiling, finite tool limits and exact child budget remain
explicit declarations. Quotes are reservations, not measured costs. Each
scenario has an isolated owner/task schema: ordinary Core still admits each
entry against Task24, Mandate40 and Day80 model-turn budgets, matching conservative
token/time allowances and Conversation=Task. The delegated child has at most4
turns,4 external calls and its declared token/time/byte envelope. The shared80
native cap supplements these normal ledgers; it creates no authority, rewrites
no reservation and cannot bypass a narrower current root/owner/day limit. The
private scenario schemas do not pretend to be one shared production owner/day.

The reference four complete workflows use17 model entries each, and Stop before
child inference uses approximately2, approximately70 actual entries in total.
This is a planning estimate, not an observed count or forced scripted transcript.
The80 cap permits finite planning variation and never permits refill, retry,
repair, fallback or continuation after a failed scenario. Final evidence reports
the actual count and every actual nullable measurement, including failures.

Fixed order: `normal_sent`, `restart_sent`, `explicit_absence`, `lost_ack`,
`owner_stop`. The healthy baseline must first complete the whole chain without
fault injection and deliver its one verified notice. The real
High planner uses ordinary Core/Broker to develop/check/trial/activate the missing
pure-IR adapter, verifies the original conversion plus prepared README patch,
and emits one stable semantic notice to the actual loopback recipient. Restart
preserves identities/effects. Explicit absence retries only that same notice.
Lost ACK preserves `delivery_unknown` without resend. Current owner Stop preserves
its same receipt, denies old child source and Broker preparation, drains the tree,
retains the two confirmed parent effects and allows zero descendant effects,
successful final or notice. No human recipient is contacted.

The wrapper requires complete unique bounded usage/version before tool/final
release and rejects provisional/conflicting metadata, empty batches,
duplicated/truncated finals, terminal-without-final and tool-after-final. A valid
single tool or complete batch proposal is a complete provider request awaiting
tool results and does not require an AssistantFinal. Before an actionable event
leaves the wrapper, its measured
terminal row must persist. Synthetic write rejection leaves the admission spent
and unknown and releases no tool/final. No SQL retry repairs that failure.
Non-actionable error events may carry only validated observed usage/version;
these measurements never grant action authority. Explicit owning cancellation
and timeout retain their original terminal kinds and exact categories. Complete
terminal-only measurements remain known; conflicts and provisional dimensions
remain NULL. Original final/terminal and STOP/MAX_TOKENS counters and uncertainty
flags are exported separately from the wrapper's safe rejection. Foreign-run
metadata cannot supply this entry's cost/version; a prior complete own
measurement survives that later failure. Nil streams consume one admission and
retain unknown measurements with a bounded entry protocol failure.

Transport representation of a batch does not grant executable batch capability.
