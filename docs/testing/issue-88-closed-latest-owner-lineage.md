# Latest closed owner/day lineage

`loadLatestClosedOwnerHistory(path, expectedSHA256)` is a read-only test-package
adapter for the next lab collector. It returns `closedOwnerDayHistory` with
`Hash`, `Day`, `Deadline`, `Carry`, inclusive `Usage`, independent `NewUsage`,
`SeparateAdaptive`, `Historical`, `Previous` and `SourceHashes`. The consumer
still checks current UTC/deadline, fixes its own finite prospective policy,
rechecks live inventory and atomically claims/imports once before admission.

The adapter explicitly supports the closed V7 manifest
`butler.memory.closed-owner-leaf.v1` and closed V8 manifest
`butler.memory.closed-owner-leaf.v2` (version8 and the prospective version9
successor). This is a fixed lab recipe,
not a new production cross-database admission mechanism. It does not assume
that145 or181 is always the latest population.

`scripts/dev/memory-closed-temporal-v8-history.py prepare BASE LABEL` copies the
original V8 prehistory and adds its actual closed ledger, all12 original
outcomes, every native entry file, exact handback, operator accounting and fresh
seven-store owner/all-owner inventories. `check-current PATH SHA256` repeats
those read-only proofs and the exact future90 namespace/receipt absence check.
Both commands reject open windows before reading any original answers or entry
content. The script uses only Python stdlib for bounded process/file handling.

The current carry is the latest corroborated inclusive scope once. Native and
product populations remain independent: admitted products without a native
entry remain charged with NULL observation. Unknown native usage remains
unknown. Failed and unexecuted originals remain in the full12 denominator.
The new stage requires both native original witnesses, exact run/reservation
links, one Start before continuations, at most12 entries per original and the
exact labelled predecessor vector. Operator metadata cross-checks original
ledger/outcome/closure digests and independent resource counts. Main credential
discovery remains separate operator accounting; unobserved invoice cost stays
unobserved. Original89v2 cause remains UNKNOWN.

The validator deep-clears only the exact latest stage, re-proves the entire
prior145 lineage and requires every other owner/schema to remain unchanged.
Historical161 and the separate adaptive226 are retained without rebilling. It
creates no model attempt, provider call, credential clone or budget row.
Semantic grading and qualification belong to separate independent reviews.

The version9 seam additionally requires the original frozen pins. Those pins
bind the source revision, exact facts5 hash, retained prospective history,
finite144/96 policy and all execution ceilings to the closed operator witness.
