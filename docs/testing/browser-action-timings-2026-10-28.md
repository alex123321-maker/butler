# Время действий браузерного агента

Метрики прошлых17 прогонов восстановлены из существующих PostgreSQL-записей.
Для этого не запускались заново сценарии, модели или браузерные действия. Три
новых прогона проверяли исправление #174, а не восполняли старые метрики.
Всего сохранены20 прогонов и188 интервалов инструментов.

Полная таблица каждого шага: [actions.csv](browser-baseline/timings-summary-20/actions.csv).
Статусы и полное время прогонов: [trials.csv](browser-baseline/timings-summary-20/trials.csv).
Интервалы модельного учёта: [model-accounting-spans.csv](browser-baseline/timings-summary-20/model-accounting-spans.csv).
Исходные JSON с переходами состояний, публикациями и доставкой находятся в
browser-baseline/timings/. Первоначальный срез17 прогонов оставлен отдельно в
browser-baseline/timings-summary/.

Это длительности целого вызова в Core, включая Broker/runtime, а не только
жеста Chromium. Отказы/UNKNOWN сгруппированы отдельно; они не делают успешный
инструмент искусственно быстрее. Наблюдения относятся к разным сборкам и
условиям; общая медиана описательная, без утверждения о p95 или нормативе.

`gap_before_s` — интервал между вызовами, включающий модель, планирование,
контекст и прочую работу. Он не объявляется чистой задержкой модели.
Модельный интервал reservation→usage также не равен чистому времени провайдера;
неизмеренные границы и NULL usage остаются неизвестными, не нулями. Интервалы
состояний, инструментов и модельного учёта перекрываются; складывать их как
независимые составляющие wall time нельзя.

Время до Telegram означает сохранённый ACK API, а не прочтение человеком.
Input completed не означает проверенный успех задачи или полное прохождение
в браузере: новый приватный аудит отдельно отмечает HTTP fallback. В новой
серии #174 доставлены3/3 правильных ответа, но точную запись браузер наблюдал
только в1/3 случаев. Исходные неудачи и ограничения полного baseline сохранены.

Для новой сборки дополнительно измерены действия оператора монотонными часами:
проверки PG/race57,31с, vet10,72с, компиляция Core8,67с, rollout+health6,94с.
Есть отдельные времена подготовки каждого получателя, HTTPS, наблюдения Input,
выгрузки метаданных и приватного сравнения. Длительности сборки взяты из Linux
uptime с разрешением10мс; операторские — Windows Stopwatch. У раннего `%3N`
выявлено неполное дополнение наносекунд нулями в uutils0.8; UTC-поля исправлены
офлайн дополнением до9 разрядов, исходные строки сохранены. Монотонные
длительности не пересчитывались, проверки ради этого не повторялись.

Воспроизведение выгрузки: scripts/dev/browser-native-timings.sh EXACT_EVENT NEW_FILE
использует только READ ONLY-транзакцию. scripts/dev/browser-timings-summary.ps1
строит CSV из сохранённых JSON, требуя новый каталог результата. Приватные
поля, аргументы, тексты страниц/ответов, cookies и credentials не экспортируются.
