# Время действий браузерного агента

Метрики прошлых17 прогонов восстановлены из существующих PostgreSQL-записей.
Для этого не запускались заново сценарии, модели или браузерные действия. Три
новых прогона проверяли исправление #174, а не восполняли старые метрики.
Всего сохранены20 прогонов и188 интервалов инструментов.

Основная метрика по уточнению пользователя — **полное время шага, включая
размышление модели и выбор следующего действия**. Отсчёт идёт от завершения
предыдущего вызова до завершения текущего; для первого — от принятия Input.
В него входят модель, контекст, очереди, ожидание согласования/пользователя,
если оно было, и сам вызов инструмента. Чистое время модели по имеющимся
границам отдельно не выделяется.

Полная таблица каждого шага: [actions.csv](browser-baseline/timings-inclusive-20/actions.csv).
Статусы, доставка и полное время прогонов: [trials.csv](browser-baseline/timings-inclusive-20/trials.csv).
Обработка после последнего вызова и прогоны без вызовов:
[finalization.csv](browser-baseline/timings-inclusive-20/finalization.csv).
Интервалы модельного учёта: [model-accounting-spans.csv](browser-baseline/timings-inclusive-20/model-accounting-spans.csv).
Исходные JSON с переходами состояний, публикациями и доставкой находятся в
browser-baseline/timings/. Первоначальный срез17 прогонов оставлен отдельно в
browser-baseline/timings-summary/. Прежний срез20 прогонов с акцентом на
длительность инструментов также сохранён в timings-summary-20/.

Отказы/UNKNOWN сгруппированы отдельно. Наблюдения относятся к разным сборкам,
контексту, месту в последовательности и ожиданиям; медианы описательные,
без утверждения о p95, нормативе или чистой скорости жеста Chromium.

`step_total_s` — полное время шага; `decision_context_wait_s` — включённый в
него промежуток до вызова. `tool_span_s` отдельно оставляет диагностическую
длительность Core/Broker/runtime. `since_input_at_end_s` показывает накопленное
время от запроса. Эти последовательные шаги вместе с хвостом полностью
покрывают время Input во всех20 сохранённых прогонах; проверка выполнена до
округления секунд, остаток менее0,01мс. Значения CSV округлены до1мс.
Два прогона без вызовов сохраняют свои25,990 и30,937с в finalization.csv,
а не исчезают из статистики и не получают нулевое время обработки.

Например, последний authority-isolation-03: Input109,969с = промежутки
модели/контекста/ожидания100,046с + вызовы инструментов2,994с + завершающая
обработка6,929с. Доставка Telegram зарегистрирована через105,264с от Input.
Начальное обнаружение инструментов также включено в шаги, не вычтено.

Модельный интервал reservation→usage также не равен чистому времени провайдера;
неизмеренные границы и NULL usage остаются неизвестными, не нулями. Интервалы
состояний, инструментов и модельного учёта перекрываются; складывать их как
независимые составляющие wall time нельзя.

Время до Telegram означает сохранённый ACK API, а не прочтение человеком.
Доставка идёт параллельно обработке; её время нельзя прибавлять к Input.
Input completed не означает проверенный успех задачи или полное прохождение
в браузере: новый приватный аудит отдельно отмечает HTTP fallback. В новой
серии #174 доставлены3/3 правильных ответа, но точную запись браузер наблюдал
только в1/3 случаев. Исходные неудачи и ограничения полного baseline сохранены.

Для новой сборки дополнительно измерены действия оператора монотонными часами:
проверки PG/race57,31с, vet10,72с, компиляция Core8,67с, rollout+health6,94с.
Есть отдельные времена подготовки каждого получателя, HTTPS, наблюдения Input,
выгрузки метаданных и приватного сравнения. Длительности сборки взяты из Linux
uptime с разрешением10мс; операторские — Windows Stopwatch. У раннего `%3N`
выявлено неполное дополнение наносекунд нулями в uutils0.8; UTC-поля исправлены
офлайн дополнением до9 разрядов, исходные строки сохранены. Монотонные
длительности не пересчитывались, проверки ради этого не повторялись.

Воспроизведение выгрузки: scripts/dev/browser-native-timings.sh EXACT_EVENT NEW_FILE
использует только READ ONLY-транзакцию. scripts/dev/browser-timings-summary.ps1
строит CSV из сохранённых JSON, требуя новый каталог результата. Приватные
поля, аргументы, тексты страниц/ответов, cookies и credentials не экспортируются.
Проверка scripts/dev/browser-timings-summary-tests.ps1 проходит восемь
синтетических offline-случаев: полное покрытие, отсутствие инструментов,
неизвестные границы, перекрытие, несогласованный/отрицательный промежуток,
инструмент за пределами Input; отдельно проверяется запрет перезаписи.
Эти проверки не запускают модели, браузер или прежние сценарии.
