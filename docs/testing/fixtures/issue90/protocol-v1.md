Draft for root/independent85 review before any issue90 inference. The experience
handler author must not use control questions/oracles to tune note extraction or
skill generation. This patch contains raw original tasks, current control tasks,
environment/reset requirements and hidden scoring rules. It contains no note
body, lesson summary, procedural step sequence or skill manifest. No source task
has yet run and no model-created lesson, skill or benefit is claimed.

Use the existing #78 acceptance ledger/collector and ordinary Butler input/run,

## Fixed population and finite window proposal

- Four original tasks, each exactly one admitted original input, no transparent
  re-execution after failure. Two independent verified successes are required for
  a skill; the other originals intentionally exercise a rejected request and an
  unverifiable committed effect. They are independent tasks/runs/recipient keys,
  not duplicated citations to one successful artifact.
- Four note-generation jobs, one per actual eligible original observation,
  each one-use through `task-experience-v1`. Runtime copies actual original
  observations; the model alone writes bounded commentary referencing real
  action IDs. Failure/unknown evidence stays negative/unknown. If an original
  cannot produce an eligible typed snapshot, retain that failure and missing
  note slot; do not substitute another original or hand-write a note.
- One model-generated skill candidate from the two actual successful accepted
  original lessons only, through existing #19. Existing fixed validation covers
  repeated verified source evidence, current contracts, failure/unknown stop and
  changed-interface rules. Validation descriptions do not prove a real trial;
  original recipient checks and independent owner results do. No hand-authored
  manifest, step correction or executable recipe may fill a rejected generation.
- Eight independent controls, two repetitions, three arms: exactly48 current
  task inputs. All48 remain in the denominator if preparation/skill availability
  fails. Record `not_executed` with its blocker; it is not a pass or an answer.
- That is52 original/control input slots plus4 note generations and1 skill
  generation,57 logical slots. Each source/control input has at most12 actual
  model transport entries including tool-result and approval continuations;
  each note-generation slot has at most1. Skill preparation is an ordinary
  foreground Flow/Broker input with at most12 actual entries: the model receives
  exact references to the two confirmed lessons as DATA and may open/page them
  before returning its strict unmodified Manifest for Stage. Prospective maximum
  is640 entries (52×12 +4×1 +1×12),
  single foreground run at a time, one actual attempt per durable input. Normal
  tool-result continuations are counted, not called retries or excluded.
- Proposed model/profile: existing Antigravity Flash High, exact32768 generated
  ceiling and300s actual provider/admission bound; all earlier root/mandate,
  input, policy and independent window deadlines still apply. Before opening the
  window root must freeze actual model/prompt/tool/runtime hashes, exact bounded
  quotes and owner/root/day limits, a finite wall deadline, and the latest private
  auth lineage. A smaller actual count is acceptable; exhausting a finite bound
  preserves all unfinished slots. No attempt occurs just because this draft exists.

Freeze source JSON hashes, rubric/protocol hashes, seed90, eight-case denominator,
two repetitions and execution order before the first original task. Freeze actual
note/skill source IDs, hashes, decisions and lifecycle generations after source
work and before the first control. A rejected source/note/skill preparation is a
real stage failure, not permission to rewrite the corpus or tune from controls.
Any later repair uses a separately reviewed prospective window and retains every

## Arm isolation, fairness and order

Every arm uses identical current user instruction, frozen profile, business tool
hashes, source data, grants/approval policy, initial recipient state, current task
constraints and per-task budget/deadline. Differences are only:

- A: no episodic notes/lessons or skills. No source-task transcript, summary,
  original result/tool bytes, note query result, skill descriptor/body or semantic
  cache may appear in any model request or tool result.
- B: the fixed accepted own-note set, under current scope/environment/lifecycle
  checks. Skill catalog/descriptions/load and bodies are disabled. No manually
  selected note per expected control answer; ordinary relevance/current scope
  selects from the entire fixed permitted set.
- C: exactly B's same fixed note set plus the one reviewed skill obtained from
  those same originals. Its independent test/review/activation/dependencies and
  source pins must be real #19 state; a compiler shortcut is not the treatment.

Experience-specific catalog surface differs as the declared treatment; all
business action authority remains identical. Any operator approval is logged and
applied by the same deterministic grant policy across arms, with equal deadline
extension policy. No custom human advice, semantic prompt correction or extra
permission is allowed after an arm fails. Count required interventions rather
than hiding them as setup.

Reset each case/repetition/arm from the same pre-run state. Normal cases start
with empty prepared artifacts, original current README and fresh task/input/run,
lease/idempotency keys. Control04 starts from the same actual original04 persisted
recipient snapshot and identical current content-free UNKNOWN effect reference;
retaining that authoritative current state in A is necessary and does not permit
its original episode/history. Control08 applies the same ordinary source deletion
after note/skill freeze to each isolated clone, uses the newest external anchor,
then reconstructs readers. Original02's unrelated lesson may survive, but no
deleted source/dependent skill may be silently recreated or reaccepted.

Leakage checks follow exact provenance, successful read/use pins, original
observation/task/run identities and unique original artifact/canary payloads.
Common independently supported wording (README.md, alpha, ready=true and the
same procedure semantics) is not proof of leakage: original02 and current live
tools legitimately repeat it. Content-free denial/audit history is not deleted
source text. `originals-v1.json` declares four exact per-original README canary
comments before any source work. The recipient preserves each comment during
the ready-only patch. Original01's exact comment and artifact provenance are
deletion canaries; they are not a required note field or a lesson-writing hint.
Original02 has a different comment and may independently support shared words.
Fresh control recipients use the declared templates and seed90 hash formula,
identically across arms, with none of the four original comments. Control04 is
the explicit exception: its real original04 recipient snapshot/comment is
legitimate current state identically in every arm; it grants no transcript or
episode access. Freeze every exact seed/file hash before original work. Canaries
cannot be invented after viewing note output or control
answers. Source content, canary and opaque instance IDs change current revision
and source hashes, not the compiled environment compatibility fingerprint. That
fingerprint still includes actual recipient/runtime contracts and readiness
semantics; v2 drift must change it while v1 alpha/beta keep it identical.

The model must use fresh logical provider contexts; no provider session/history,
retrieved result, answer, turn checkpoint, Working Memory or semantic answer cache
is shared between arms. Ordinary Working Memory of the *current* task is retained
within that task in every arm. Authentication/transport metadata caches may be
shared only when they contain no task/source/model text and costs remain visible.

Disable learning from all control outputs until the whole frozen comparison is
closed. Private evaluation exports are not accepted Catalog lesson/skill sources.
No second-generation note, skill repair, policy tuning or corpus filtering may
use a control question, oracle or answer during the comparison.

Order is fixed, not chosen after outcomes. For case index i=0..7, repetition1 uses
the cyclic rotations of A,B,C by i mod3; repetition2 uses the same rotations of
C,B,A. Run cases in ascending ID within each repetition. Source tasks run01..04,
then note generation01..04, then skill generation/test/review/freeze. Retain every
actual request hash, selected note/skill digest and effective visible source set.

## Cost and outcomes

Per slot retain actual task outcome/criterion results, old failure repetitions,
misapplied experience, unknown effects, source/environment/permission denials,
task elapsed time, owner interventions and all model/tool events. Include every
source, note extraction/write, query/retrieval, skill generation/test/review/load,
current-task inference, continuation and possibly-sent/failed attempt in durable
ledgers. Missing usage/invoice is unknown, never zero. Synthetic subscription
price basis is not a measured monetary invoice. Retain input/output/non-input
usage, bytes, server/transport/model versions and end-to-end time separately.

Let S be actual shared original execution cost, N note creation/review/write cost,
K skill generation/test/review/activation cost, and QA/QB/QC each arm's full48/3=16
current-task query/retrieval/use costs. Report:

- A full allocated cost: S+QA.
- B full allocated cost: S+N+QB. B−A=N+QB−QA isolates own-note contribution.
- C full allocated cost: S+N+K+QC. C−B=K+QC−QB isolates the extra skill contribution.
- Actual unique experiment spend: S+N+K+QA+QB+QC. Do not add the three allocated
  totals and triple-count source work or duplicate shared notes.

Report one-time preparation and marginal repeated-task costs in addition to those
full totals, both overall and by case/repetition. The prescribed workload is16
current tasks per arm; no favorable amortization horizon may be chosen later.
Unknown components make a total/ratio unknown or explicitly a lower bound. Quality
and cost are separate outcomes; no gain or regression is valid. A C-only advantage
does not establish own-note benefit in B. A failed/unexecuted slot stays in the
original denominator and cannot be replaced by a generated fallback answer.
