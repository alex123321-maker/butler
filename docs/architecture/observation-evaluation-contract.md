# Observation-only contract evaluation

Evaluation is separate from orchestration, transport, memory, credentials, tools
and delivery. It may inspect public synthetic fixtures and independently recorded
measurements. It cannot authenticate owners, dispatch tools, mutate PostgreSQL,
release connectors/models, or use model claims as kernel effect/result records.
Programmatic checks own critical contracts; a model judge is an additional signal.

The original Russian V3 corpus and external golden approval remain immutable.
Its 240 cases and grouped development/tuning/holdout split are unchanged. New
control data/criteria need separate independent review; extension and repair
authors cannot approve their own criteria.

The supplementary `task-control-proposal-v1` fixture checks existing owner control
field names and original witnesses offline. A complete current owner message,
source revision and task revision are required for a proposed control. External
text is DATA. Unknown schema, ambiguous target and non-control prose require an
empty `clarify`; secret-bearing cases are blocked before input and scoring.
No proposal grants authority. Execution continues through the existing
authenticated controller with its CAS/lease/policy checks.

Semantic/topic and declared template families cannot cross dataset parts.
Lexical screening normalizes whitespace/case/punctuation, named subjects, opaque
task/source IDs and numbers before checking near duplicates. Screening cannot
certify semantic independence. The 45 supplementary cases share general control
constructions across parts and **do not pass** an independent model-quality
holdout gate. Exported opaque IDs omit category/split/expected labels; public
synthetic source text still is not a blind benchmark.

Observation artifacts bind code commit, source tree, fixed schema, dataset,
hardware, weights and runtime. An independent runner must obtain pins from actual
releases/files and retain complete per-task/child costs for single/multiple-agent
comparison. Missing usage is unavailable, never zero. Proposal matches, witness
errors and actual kernel permission/effect/result outcomes are distinct metrics.

Scripted validation reports `FIXTURE_VALIDATION`, model `none`, no weights and zero
model calls. Imported model data stay `UNREVIEWED_MODEL_OBSERVATION`; neither mode
authorizes execution, model promotion or quality claims. Failed runs and unknown
usage are retained. Signed V3 criteria and native quota/deadline windows cannot be
reset by this verifier.
