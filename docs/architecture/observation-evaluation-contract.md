# Observation-only contract evaluation

Evaluation is separate from orchestration, transport, memory, credentials, tools
and delivery. It may inspect public synthetic fixtures and independently recorded
measurements. It cannot authenticate owners, dispatch tools, mutate PostgreSQL,
release connectors/models, or use model claims as kernel effect/result records.
Programmatic checks own critical contracts; a model judge is an additional signal.

The original Russian V3 corpus and external golden approval remain immutable.
Its 240 cases and grouped development/tuning/holdout split are unchanged. New
control data/criteria need separate independent review; extension and repair
authors cannot approve their own criteria.

The supplementary `task-control-proposal-v1` fixture checks existing owner control
field names and original witnesses offline. A complete current owner message,
source revision and task revision are required for a proposed control. External
text is DATA. Unknown schema, ambiguous target and non-control prose require an
empty `clarify`; secret-bearing cases are blocked before input and scoring.
No proposal grants authority. Execution continues through the existing
authenticated controller with its CAS/lease/policy checks.

Semantic/topic and declared template families cannot cross dataset parts.
Lexical screening normalizes whitespace/case/punctuation, named subjects, opaque
task/source IDs and numbers before checking near duplicates. Screening cannot
certify semantic independence. The 45 supplementary cases share general control
constructions across parts and **do not pass** an independent model-quality
holdout gate. Exported opaque IDs omit category/split/expected labels; public
synthetic source text still is not a blind benchmark.

Observation artifacts bind code commit, source tree, fixed schema, dataset,
hardware, weights and runtime. An independent runner must obtain pins from actual
releases/files and retain complete per-task/child costs for single/multiple-agent
comparison. Missing usage is unavailable, never zero. Proposal matches, witness
errors and actual kernel permission/effect/result outcomes are distinct metrics.

Scripted validation reports `FIXTURE_VALIDATION`, model `none`, no weights and zero
model calls. Imported model data stay `UNREVIEWED_MODEL_OBSERVATION`; neither mode
authorizes execution, model promotion or quality claims. Failed runs and unknown
usage are retained. Signed V3 criteria and native quota/deadline windows cannot be
reset by this verifier.

## Explicit cloud shadow evidence

The separate cloud path keeps the signed V3 corpus, old local-weight scorer and
comparison unchanged. It pins the requested cloud profile, observed nullable
provider version, code/source/runtime/schema/policy/data/client-hardware and
allowances. Proprietary weights must be `unavailable` with a NULL SHA; remote
hardware/memory and subscription invoice remain unavailable rather than invented.
Equal client allowances do not establish identical proprietary cloud hardware.

Opaque inputs exclude four secret-bearing cases and all expected labels. Before
any live observations, the independent root freezes the fixed 236-case policy and
four original comparison tasks. No retry, resampling, threshold override or
holdout retuning is permitted. Programmatic schema/source/authority checks own
critical results. Synthesis gets original witnesses and two child answers as DATA,
never a model verdict or majority truth. Shadow contexts do not claim kernel
delegation; actual product chain evidence remains separate.

All attempts retain input/output/total token measurements, including thinking
tokens, explicit NULLs, latency and client-memory scope. Full token cost is denied
if any count is unknown. Failed children cannot disappear from comparison spend.
Client global RSS and remote model RAM are distinct. Billing cannot be inferred
from subscription membership. Native identity requires independent correlation
with the charged ledger and immutable report; fixture success is never model
quality and neither scorer authorizes execution or automatic deployment.

Cloud API and exact thresholds/reproduction: `internal/acceptance/cloud_observation.go`
and `cmd/cloud-observe/README.md`. External key/approval identity and original
signature are checked before import; candidate code cannot issue approvals.

Implementation/reproduction: `internal/acceptance/command_suite.go`,
`cmd/command-observe/README.md`, `scripts/dev/scenario-corpus-lab.sh`.

## Current mandatory product faults

`internal/acceptance.FullFaultGroups/FullFaultScenarios` and
`FaultCriteriaDigest` define the separate `butler-mandatory-faults-v3` gate.
They do not alter the independently signed V3 `CriteriaDigest`, original matrix
or corpus. Current exact event names, source/schema/criteria/hardware pins,
actual Chromium, PostgreSQL and dump/restore are required; missing, skipped,
duplicate or foreign events fail. Fault-run writes an exclusive initial release
pin before tests; fault-report rejects changed source/schema/hardware identity.

The actual model fault is one separately sealed cached Qwen3 CPU **load** under
256 MiB RAM/swap with no GPU, network, HTTP, prompt or inference. Verified image,
weights, manifest and current runner bytes, read-only single weight mount,
GGUF metadata read, Docker exit137 and OOMKilled are required. This physical
runtime proof is separate from controlled kernel/owned-worker failure tests and
does not assert Butler received this OOM. Remote High RAM/OOM are unavailable.
Fault-only output never approves model quality, enables authority or sets full
issue readiness. Complete original-task/one-notice release-chain faults and
independent pinned High quality/cost observations remain separate required gates.

The original physical report's complete-metadata-line detector remains FAIL and
metadata_read=false. The separately reviewed vocabulary witness-v2 fixes that
detector's narrow logger assumption without rewriting it: exact immutable report,
log and global one-start hashes plus ordered model-specific loading/vocabulary
markers and original OOM/isolation are required. It proves only entry into GGUF
vocabulary metadata processing before physical OOM, not completed weights,
inference, remote High OOM or Butler kernel propagation. Reviewer/root approval
is a fixed source-reviewed hash pin, not a claimed signature or administrative
isolation. The precise primary logger premise is recorded in the current plan.
