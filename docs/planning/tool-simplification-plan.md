# План упрощения инструментов Butler

Дата: 19 октября 2026, Asia/Tomsk. Основание: `main` на `405a096b`.
Статус: поэтапная реализация. Выполнены перемещение Converters в Advanced,
[исходный аудит](../testing/web-tools-audit-2026-10-19.md) и исправления шести
дефектов [этапа 1 с проверкой через Broker](../testing/web-tools-stage1-2026-10-19.md).
Выдача по запросу реализована параллельной работой в `main` (`57156dd5`):
[tools.search/load](../architecture/tool-discovery.md). Серверный браузер с
публичной multi-origin навигацией и приватным owner-control каналом реализован
в этой ветке; [приёмка](../testing/server-browser-2026-10-19.md) отделена от rollout.
Последующие объединения namespace ниже остаются планом.

Решения пользователя после аудита: основной браузер — серверный, без ограничения
на один origin, с просмотром и ручным управлением в Butler Web. `single_tab`
отложен: все 15 legacy-контрактов выключены в стандартном каталоге. Текущие browser runtime
guards этим документом не отключаются; миграция имеет отдельную приёмку.

## 1. Результат, который нужен

Агент выбирает инструмент по задаче, а не между несколькими похожими описаниями
«прочитать сайт». Обычное чтение не требует загрузки всех browser/auth/extension
схем. Каждый результат честно сообщает HTTP-ошибку, ограничение или неполноту.

В интерфейсе возможностей достаточно трёх групп:

1. **Веб**: прочитать страницу, извлечь данные из полученного документа.
2. **HTTP / API**: запрос к API, получение файла как артефакта.
3. **Браузер**: серверный браузер Butler с окном и ручным управлением в Web.

Группа интерфейса, namespace контракта и контейнер — разные вещи. На первом
этапе контейнеры не объединяем. Сетевой reader, credential-aware HTTP runtime,
изолированный Chromium сохраняют свои границы. Пользовательский native host
выведен за пределы стандартного целевого сценария.

## 2. Решение по каждому набору

| Сейчас | Решение | Целевая семантика / условие удаления |
|---|---|---|
| `web.fetch` | Оставить основным reader | Один URL, проверенный HTTP-статус/MIME, ограниченный текст, ссылки и provenance; явные ограничения, без скрытого запуска браузера или передачи третьей стороне |
| `web.extract(url/html/text)` | Сузить и объединить с HTML-парсером | Только уже полученное содержимое: предпочтительно текущий `source_ref`, допустим небольшой bounded inline HTML; без сетевого URL. Сохранить простой selector, явно отклонять неподдержанный синтаксис |
| `http.parse_html` | Вывести из нового публичного каталога | Его локальное извлечение переходит в `web.extract`; сетевой путь заменяется явными `web.fetch` + `web.extract`. Удалять после миграции действующих контрактов |
| `web.fetch_batch` | Убрать из базового v1-набора | Последовательные `web.fetch` дают отдельные результаты и контроль бюджета. Старые вызовы доживают на своих версиях. Возвращать batch только при измеренной пользе и доказанном учёте всех URL/байтов/исходов |
| `http.request` | Оставить в API-наборе | Явные method, URL, bounded body, mediated credentials; read/write эффекты и подтверждение внешней записи различаются |
| `http.download` | Заменить контракт новой ревизией | Сохранение bounded бинарного файла в существующее хранилище артефактов; `artifact_ref`, MIME, size, digest, source. Превышение лимита — явная ошибка, без выдачи обрезанного файла как полного |
| `browser.read` | Оставить, загружать только для rendered read | Отличается от `web.fetch` исполнением JavaScript. Отдельная операция с собственной проверкой доступа; renderer не становится незаметным fallback reader-а |
| `browser.open/snapshot/navigate/extract_text/wait_for/close` | Оставить с выдачей по состоянию | Первоначально только open/read; после успешного open — необходимые операции над этой сессией |
| `browser.prepare_fill/prepare_type/click` | Основной набор для форм | Подготовка при замороженной сети; отправка — отдельный разрешённый click; неизвестный исход не превращается в успех |
| `browser.fill/type` | Убрать из стандартного набора форм | Legacy live input может вызвать autosave. Оставить временную совместимость; отдельная выдача только при доказанной необходимости и соответствующей политике |
| `browser.set_cookie/restore_storage_state` | Отдельный auth-набор | Загружать при разрешённом сценарии входа; только `credential_ref`, без raw cookie/storage в модели |
| `single_tab.*` | Отложить и убрать из целевого стандартного каталога | Основная работа выполняется в серверном браузере с owner control в Web. К режиму локальной вкладки вернуться только при отдельной потребности в сессии на устройстве пользователя |
| `converters.*` и `converter.<id>.convert` | Не включать в обычный веб-набор | Управление — Advanced. Показывать только при разрешённой задаче преобразования таблицы и готовой подсистеме |

`browser.fill` и `prepare_fill` нельзя просто объявить алиасами: у них разные
сетевые эффекты. Нельзя заменить `single_tab` серверным браузером при ошибке или
наоборот: это другая сессия, авторизация и поверхность пользовательских данных.

## 3. Выдача агенту только нужных инструментов

### 3.1 Существующая основа

В Broker уже есть task-scoped `ListTools(run_id, query, limit)`. Он проверяет
текущего владельца, lease, task/mandate, deny-list, delegation и readiness.
`query` сейчас является фильтром по словам; результат сортируется по имени и
обрезается до 64. Это ещё не поиск по релевантности. Orchestrator вызывает
`ListToolsForRun` без запроса, превращает весь ответ в tool definitions и также
формирует текстовый tool summary.

Используем этот каталог и существующий kernel; отдельный сервер каталога,
vector index, новый LLM-классификатор и универсальный `execute_tool` не нужны.

### 3.2 Начальный набор и обнаружение

- Для обычного разговора — ноль веб-инструментов; необходимые управляющие
  инструменты ядра определяются ролью и текущим поручением отдельно.
- Для явной просьбы прочитать указанный URL можно сразу добавить `web.fetch`.
- Добавить один read-only инструмент ядра `tools.search` с bounded запросом и
  необязательной категорией `web_read/api/browser/data_transform`.
  Он помогает обнаружить допустимую возможность, но не выполняет её.
- Категории имеют короткие русские/английские описания. Это позволяет найти
  reader по слову «страница», а не только по английскому имени функции.
- Поиск сначала применяет актуальную policy/readiness-фильтрацию Broker,
  затем ранжирует/группирует результат. Не раскрывает скрытые capabilities,
  содержимое вкладок, имена аккаунтов или credentials.
- Возвращать до 6 кандидатов. Kernel получает их полные схемы из доверенного
  каталога, а не из текста страницы, навыка или модельного ответа, и добавляет
  выбранный небольшой набор к следующему шагу модели.
- Цель: 0–1 веб-схема при старте; типичный рабочий набор 5–8 операций;
  максимум 12 дополнительных схем одновременно. Обязательные kernel controls
  не отрезаются ради этого лимита. Нужная операция всегда обнаружима повторно.

### 3.3 Выдача по состоянию

| Ситуация | Набор |
|---|---|
| Прочитать статью по URL | `web.fetch`; extract только если нужно выбрать часть документа |
| Нужен JavaScript, API ещё не нужен | Обнаружить `browser.read`; проверить отдельный доступ |
| Заполнить форму в браузере Butler | `browser.open`, затем snapshot/prepare/click/wait/close по текущему шагу |
| Пользователь хочет смотреть или управлять браузером | Окно текущей серверной сессии в Web; явная передача управления owner/agent |
| Вызвать REST API | `http.request`; выдача схемы не разрешает POST и не заменяет exact-action policy |
| Получить PDF/архив | Новая `http.download`, затем ссылка на артефакт. Чтение PDF отдельной возможностью, которой этот план не объявляет существующей |
| Преобразовать CSV | Только доступные инструменты data-transform; converter developer не загружается на каждое чтение веба |

Активная браузерная сессия остаётся run-owned и ограничена TTL. Текущая
реализация дополнительно ограничена origin; целевая версия снимает эту границу.
Новый run не наследует её автоматически. После close/expiry инструменты текущей
сессии убираются; после потери состояния необходим новый явный open/bind.

### 3.4 Обновление, восстановление и полномочия

1. Orchestrator хранит bounded selection в существующем checkpoint: имена,
   hash/revision контрактов и контекст task/resource; без body/credentials.
2. Перед каждым новым model turn, после approval и recovery перечитывается
   живой каталог. Отозванные или изменённые схемы исключаются, stale выбор
   не восстанавливается из старого provider context.
3. Prepare/Authorize/Claim/Execute сохраняют текущие проверки action/task/
   source/authority/budget независимо от того, видел ли агент схему.
4. Вызов вне выданного набора не исполняется; ошибка предлагает discovery без
   раскрытия скрытого каталога. Поиск не расширяет mandate или права ребёнка.
5. Обновление tool definitions проверяется на поддерживаемых transport-адаптерах.
   Если provider continuation не умеет обновить набор, kernel создаёт новый
   provider request из канонического transcript под текущим run/lease. Это не
   повторный tool dispatch и не перенос authority в provider session.
6. Удаляется повторение длинных descriptions в prompt summary: остаётся короткая
   инструкция о поиске и режимах, полная схема передаётся один раз как tool.

Нельзя делать автоfallback с неизвестного эффекта click/POST на другой runtime.
Публичный IP не является разрешением отправить содержимое частного URL/query
внешнему reader-провайдеру. Jina остаётся явным opt-in с отдельной release policy.

## 4. Этапы, зависимости и проверка

### Этап 0 — небольшой UI-шаг (выполнен в этой ветке)

Перенести Converters из Workspace в Advanced, сохранить URL и owner-controls.
Проверено: typecheck, ESLint, Stylelint, production build, существующий Chromium
сценарий страницы; скриншот показывает новый пункт в Advanced. На сервер не
развёрнуто. Backend converter flags и полномочия не меняются.

### Этап 1 — корректность результатов (P0, до сокращения контрактов)

Шесть воспроизведённых дефектов исправлены, постоянные runtime tests и
Broker/PG/gRPC acceptance проходят под race detector. См.
[evidence и точную границу](../testing/web-tools-stage1-2026-10-19.md).
Объединение всех reader outcomes в новый общий typed response ниже остаётся
следующей работой; текущий этап сохраняет действующий fetch контракт и даёт
revision2 для расширенного результата extract.

Исправить шесть воспроизведённых дефектов из аудита: script/style в тексте,
потерю HTTP-статуса, скрытую обрезку, binary-as-text, молчаливый неподдержанный
selector и `matches:null`. Уточнить типизированный результат reader-а:
`status`, `http_status`, `requested_url/final_url`, `mime_type`, `provider`,
`truncated`, объём, текст или source/artifact ref, безопасная ошибка/ограничение.
HTTP 404/429/5xx, redirect, unsupported MIME, timeout, unavailable provider и
пустой документ должны различаться. Ни runtime `completed`, ни HTTP 200 сами
по себе не означают, что запрошенный документ прочитан полностью.

Redirect policy сейчас запрещает следование. Сначала вернуть понятный исход;
будущий bounded redirect — отдельное изменение: проверка каждого hop/DNS,
credential stripping, лимит hops/bytes/deadline, текущая release authority.
Не снимать SSRF/origin ограничения ради прохождения happy-path.

Приёмка: все шесть audit reproductions становятся зелёными после переноса в
обычные regression tests; static HTML/Unicode, 404/429/500, превышение лимита,
PDF/binary, пустой/unsupported selector, redirect/private-hop, DNS rebinding,
secret reflection проверены через runtime и реальный Broker с PostgreSQL.
Отдельно — public GET smoke без account credentials. Ни одного обязательного skip.

### Этап 2 — убрать дублирующие операции (P1, после этапа 1)

Ввести local-only `web.extract`, артефактный download; перестать рекламировать
`http.parse_html` и `web.fetch_batch` для новых run. Сохранить результаты,
provenance, лимиты и различие отсутствия совпадений/ошибки синтаксиса.

Приёмка: один сценарий получения страницы имеет один стандартный путь; выбор
по selector не потерян; файл скачивается byte-for-byte с проверяемым digest;
большой файл не уходит в model context; старые pending approvals не могут
исполнить новую семантику под старым hash.

### Этап 3 — discovery и bounded model catalog (P1, после этапа 2)

Расширить существующие Broker catalog/Orchestrator preparation/recovery и
transport continuation, не создавать отдельную orchestration-подсистему.
Покрыть `tools.search`, категорийный поиск, stable ranking, свежесть selection,
схемы в следующем turn, смену задачи, revocation и восстановление.

Приёмка: в обычном разговоре отсутствуют browser/auth/converter definitions;
URL-reader получает только нужный набор; поиск на русском/английском находит
допустимые инструменты; нет алфавитного вытеснения нужных схем лимитом64;
отзыв mandate/source/lease и смена версии контракта исключают stale схему;
delegate видит только своё подмножество. Ни один discovery-вызов не вызывает
сетевой runtime и не предоставляет права на последующее действие.

### Этап 4 — браузерные наборы и реальная применимость (P1, после этапа 3)

Подключить выдачу по open/expiry, стандартный prepare-first сценарий форм и
отдельную auth-выдачу. Удалить `single_tab` из стандартной конфигурации и выдачи
для новых run; существующие разрешённые привязки завершить/отозвать через их
владельца, затем отключить optional composition. Исторические записи сохранить.

В отдельной новой ревизии browser contracts снять fixed-origin ограничение
навигации и ресурсов: поддержать обычные публичные переходы, CDN и SSO.
Модельные действия по-прежнему проходят current task/mandate/action guards;
доступ к private IP/localhost остаётся закрытым, credential refs разрешаются
только для действительного текущего адреса. Встроенная same-origin policy
Chromium и ограничения cookies не отключаются. Межсайтовый переход меняет
наблюдение и не переносит approval на другую страницу.

Добавить в Web окно серверной сессии с просмотром, мышью и клавиатурой.
Реализуемый вариант без desktop window на ноутбуке — внутренний CDP screencast
и типизированные input operations через owning kernel. Raw CDP endpoint наружу
не публикуется. [Chrome Page API](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-startScreencast)
и [Input API](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-dispatchMouseEvent)
дают необходимые низкоуровневые операции; совместимость проверять на pinned
Chromium. CDP screencast experimental, поэтому до реализации проверить ACK,
доступные методы, частоту кадров и fallback на bounded screenshot transport.

Управление имеет одного владельца. Owner takeover приостанавливает модельные
действия через общий resource fence; ручной input идёт через authenticated
owner/kernel path с текущей session authority. После возврата управления агент
получает свежее наблюдение и переоценивает действие. Mouse/key события, пароли
и clipboard не становятся transcript/model DATA. Кадры owner viewer доступны
только владельцу; попадание screenshot в модель — отдельная безопасная проекция.
Unknown effect не превращается в подтверждение из-за ручного вмешательства.

Приёмка: простая форма, подготовка без autosave, stale DOM, TTL,
crash/lost ACK, ручное изменение страницы, два исполнителя, owner revoke,
секреты и запрет private-network egress. Публичные переходы между origin,
CDN и SSO входят в положительную матрицу. Для popup, iframe, WebSocket и
POST-based SPA явно определить поддержанный scope; каждый неподдержанный
сценарий должен иметь понятное ограничение.
Отдельно проверить owner takeover/return, одновременные попытки ввода,
отключение viewer, resize, stale frame coordinates, маскирование model projection,
SSO с несколькими origin и изоляцию двух browser sessions. Пользовательский
экран не должен передаваться model provider как постоянный поток.

### Этап 5 — измерение и управляемое включение (после 1–4)

Зафиксировать одинаковую версию модели, задачи, policy и бюджеты для старого
и нового каталога. Набор задач: URL-статья, несколько URL, 404, PDF, простой
API, SPA, форма, ручное управление серверным браузером, отсутствующая возможность,
посторонние инструкции в странице. Минимум 10 сценариев с заранее заданными
внешними критериями результата, а не оценкой моделью собственного ответа.

Сравнить correctness/blocked reason, число схем и их bytes/tokens, число
discovery/tool/model calls, latency и фактическую стоимость, если она известна.
Новый каталог должен снизить context bytes и сохранить результат/безопасность;
рост discovery turns явно учесть. Не обещать экономию только по числу имён.
Native comparison не выполнен в текущем аудите.

Включать для ограниченного operator profile после проверок. Rollback возвращает
старую выдачу совместимых схем, не отменяет уже выполненные эффекты и не
оживляет отозванные полномочия. Переключение production отдельным rollout,
не автоматическое следствие merge.

## 5. Совместимость и документация

- Имена и revisions входят в approval/action/mandate/delegation hashes. Не
  перенаправлять старое имя на новые аргументы или эффект через скрытый alias.
- Для новой семантики — явный revision/переходный контракт и новые approvals.
  Существующие grants не мигрировать расширяющим преобразованием.
- Старые версии обслуживают только уже разрешённые совместимые действия до
  завершения/отмены; необратимые/unknown effects не повторяются при миграции.
- После опустошения pending state обновить skills, prompts, extension references,
  fixtures, конфигурацию и затем удалить legacy dispatch.
- В каждом этапе синхронно менять relevant architecture spec, runtime README,
  contract tests и operator docs. Нынешний документ — target plan, не замена
  действующим контрактам.

## 6. Что отложить или не делать

- Не объединять runtime-контейнеры до измерения реальной эксплуатационной цены.
- Не добавлять универсальный `web.do(action=...)`: он скроет разные effects и
  ухудшит точные схемы/approval-аудит.
- Не удалять браузерный reader как «полный дубль HTTP»: JavaScript — отдельная
  возможность, но её не нужно показывать всегда.
- Снятие fixed-origin ограничения реализовать явной новой браузерной ревизией;
  egress, credential и exact-action guards сохранить на новой области навигации.
- Не превращать конвертор таблиц в обязательную основу всего саморасширения.
- Поиск по интернету (`web.search`) сейчас отсутствует: reader работает по URL.
  Отдельный search provider не включён в этот план упрощения.
