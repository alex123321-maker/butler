# Память: сценарии и упрощение интерфейса

Дата: 2026-10-23. Область: существующий Web-модуль `features/mind`, без новых
сервисов, зависимостей приложения и изменений модели хранения памяти.

## Рассмотренные варианты

| Вариант | Где полезен | Компромисс | Решение |
| --- | --- | --- | --- |
| Поиск, список, чтение рядом | Вспомнить сообщение, найти документ, сверить факт | Нужно сохранять контекст между результатами и открытой записью | Основной режим; чтению отдано больше ширины |
| Граф как основной экран | Исследовать происхождение и переходить между связанными записями | Без связей мало полезен; положение узла не помогает найти конкретную фразу | Дополнительная «Схема связей», без обязательного выбора вкладки |
| Хронологическая лента | Просмотреть недавние события | Дата события и дата сохранения различаются; плохо подходит для точного поиска | Пустой запрос показывает недавние записи; отдельную ленту не добавляем |
| Таблица с постоянными фильтрами | Массовый аудит статусов, источников и версий | Усложняет обычное чтение; локальные фильтры создадут ложное впечатление поиска по всей базе | Подробное администрирование остаётся в существующем разделе |

Сопоставлены официальные описания [поиска Notion](https://www.notion.com/help/search),
[поиска Obsidian](https://obsidian.md/help/Plugins/Search),
[локального графа](https://obsidian.md/help/Plugins/Graph%2Bview) и
[обратных ссылок](https://obsidian.md/help/plugins/backlinks).
Из этих подходов взяты недавние запросы, клавиатурный вход в результаты и связи
в контексте открытой записи. Это сравнение описанных сценариев, а не тестирование
чужих приложений на данных владельца.

Принципы [узнавания вместо припоминания](https://www.nngroup.com/articles/recognition-and-recall/)
и [постепенного раскрытия](https://www.nngroup.com/articles/progressive-disclosure/)
поддерживают выбор: показать полезное содержимое сразу, а редкие подробности
раскрывать по запросу. Удобство именно для владельца остаётся гипотезой до
реального использования; автоматические тесты проверяют поведение, не удовлетворённость.

## Основные сценарии

| Задача | Теперь | Убрано или исправлено |
| --- | --- | --- |
| Найти знакомую запись | Поиск по словам, двухстрочный фрагмент, до пяти недавних запросов | Повторный ввод уже использованных слов |
| Прочитать с телефона | Одно нажатие на результат; «К списку» или Escape возвращают позицию и фокус | Второе нажатие «Открыть» и вложенное окно |
| Проверить происхождение | Подпись под связью и раскрытие «Источник и история» | Отдельное окно «Почему связаны?» и повтор полного текста источника |
| Пройти по цепочке записей | Связь → запись → назад/вперёд с новым чтением API | Потеря пути и необходимость заново искать исходную запись |
| Проверить предложенный факт | Явные «Подтвердить факт» / «Отклонить факт», затем серверный статус | Односторонний выбор и автоматические повторные мутации |
| Исправить источник | Управление открывается с точным `source_id` | Повторный поиск записи в административном каталоге |
| Использовать текст вне модуля | Явное копирование полного просмотренного текста | Необходимость вручную выделять длинный текст |
| Ничего не нашлось | Подсказка по словам и кнопка возврата к недавним записям | Пустой тупик |
| Работать с клавиатуры | Ctrl/Cmd+K → Down → стрелки/Home/End → Enter | Мышь как обязательный способ выбора |

Выбранная запись сохраняется при поиске. Если её нет среди результатов, рядом
появляется «Вне текущего списка». Схема в этом случае показывает загруженные
результаты вместо пустой области. Временные закрепления убраны: они выглядели
как настройка долговечной памяти, но существовали только до закрытия просмотра.

## Границы достоверности

- Поиск остаётся серверным текстовым; UI не обещает семантический поиск.
- Числа и схема относятся к загруженным страницам, а не ко всей базе.
- Стрелки обозначают сохранённое происхождение, не доказанную истинность.
- Недавние запросы живут в памяти страницы и очищаются при смене владельца.
- Назад/вперёд не возвращают кэшированное содержимое; выполняется новое чтение.
- Недоступные/отозванные источники и secret-версии не показывают содержимое.
- Подтверждение и отклонение используют текущий observed active claim ID;
  конфликт требует проверки состояния. Запись источника не равна подтверждению.
- Отзыв доступа со стиранием не маскируется под обратимую паузу.

## Проверка

`memory-explorer.spec.ts` и `mind.spec.ts` проверяют поиск, возврат, источник,
историю, граф, клавиатуру, clipboard-действие, точный переход в управление,
оба решения по факту, конфликт, пагинацию и защиту от запоздалых ответов.
Экраны 320/390/768/1440 px проверяются на выход за границы и визуально по снимкам.
Ответы API в этих тестах синтетические; они не заменяют проверку реального
серверного хранилища или пользовательское исследование.
