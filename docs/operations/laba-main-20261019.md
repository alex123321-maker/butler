# Основной Butler на laba: 19 октября 2026

Основная рабочая БД перенесена с `butler-local` на ноутбуке в **butler-main**
на `ssh laba`, `/srv/storage/butler/main`. Это отдельный Compose project с
собственными PostgreSQL, Redis, Broker, Core, runtimes, ingress и Web.
Старые Core/Broker/Web проекта `butler-lab` и локальные Core/Broker/Wi-Fi
остановлены. Старые БД и резервные копии сохранены; два обработчика одних
уведомлений не запускаются. Тяжёлые local-models/parser используют уже
подготовленные private services/storage на laba, без второго экземпляра моделей.

## Доступ и управление

- Web: <http://192.168.0.5:3080>, Companion: `/mobile`.
- Owner/API: <http://192.168.0.5:8088>; существующий owner token сохранён.
- Companion device-only ingress: `http://192.168.0.5:18061`.
- Конфигурация: `/srv/storage/butler/main/compose.json`, mode0600; содержит
  приватные значения, её нельзя публиковать или выводить целиком.
- Статус: `ssh laba 'docker compose -f /srv/storage/butler/main/compose.json ps'`.
- После установки проверенных бинарников: тот же Compose `up -d`.
- Исходники текущего выпуска: `/srv/storage/butler/current`, версия/хэши:
  `/srv/storage/butler/main/deployed-main.json`.

`lab.sh Status` при наличии нового manifest показывает butler-main. Старый
`lab.sh Up` отказывается поднимать второй primary; обычный source Sync не
устанавливает бинарники нового artifact deployment. Не запускайте первоначальные
provision/pair scripts поверх живой базы и не используйте `down -v`.

Новые флаги не расширяют существующий телефонный мандат, права child-ролей или
неизменяемые потраченные бюджеты. Для фоновых потребителей нужны точные конечные
owner policies на выбранные источники; отсутствие таких policies не заменяется
самостоятельно придуманным разрешением на всю личную историю. UI/Doctor честно
показывают `composed/current_authority_required`, `unknown` или отсутствие
активированных индексов, а не фиктивный verdict качества.

## Перенос и доказательства

Перед переключением сделаны private `pg_dump` обеих рабочих БД, копии актуальных
независимых deletion manifests и соответствующих ключей. Локальный backup находится
в `D:/CodexData/deployments/butler-local/private/backups/`; серверные копии —
`/srv/storage/butler/main/import-local` и `reports/old-laba-backup`.
Restore в пустую БД выполнен с `--exit-on-error`, затем обычный migrator проверил
весь набор: 83 применённых миграции, включая085. Старый standalone lab содержал
67 миграций; его данные не смешивались с рабочей телефонной БД.

Android по USB остановлен с временно отключённым listener. Сделан private backup
зашифрованных app state/SQLite/preferences. Изменён только серверный адрес в
конфигурации **того же восстановленного Butler**; device ID и encrypted token
сравнены до/после, очередь и Keystore не очищались. Listener восстановлен.
Установка APK, перепривязка и сброс device credentials не выполнялись.
Первый новый receipt принят на laba 18 октября18:59:23 UTC
(19 октября01:59 Asia/Tomsk); accepted_count вырос209→210. API телефона без proof даёт401,
административные пути на device ingress —404. Это доказательство доставки,
отдельное от обработки уведомлений моделью.

Из локального dump унаследован blocked phone batch с неизвестным `memory.search`.
Старый task остановлен через authenticated owner control; неизвестный effect и
spending сохранены. Через owner CAS источник получил новую ревизию, Observer
освободил непрочитанные сообщения и создал новое ordinary задание. При включении
всех фич исправлены private Broker proxy bypass и ошибка skills/discovery chain;
состояния прерванных попыток не объявлены успешными и не удалены.

Дополнительно закрыто ошибочное представление memory.search: когда adaptive
reader отсутствует, native schema не предлагает semantic_hybrid и фильтры дат.
Неподдерживаемый вызов из старой схемы сохраняет прежнее неизвестное состояние;
оно не превращено в подтверждённый эффект. Новый пакет использует текущую схему.

После исправлений фоновая Gemini выполнила новый20-message batch:19 записей
получили ignored,1 — noise, все20 `messages.process` имеют реальные завершённые
receipts. Run завершился; следующий пакет автоматически начал работу. Исходные
записи не удалены, текст личных сообщений/ответов не экспортируется в отчёт.
Эти counters подтверждают исполнение, но не независимую смысловую оценку решений
модели. Непрочитанный остаток продолжает обрабатываться в рамках старых конечных
owner/day/mandate budgets. Безопасный
[snapshot развёртывания](../../deploy/tool-discovery/laba-deployment-20261019.json)
содержит service/binary/config hashes, состояния, flags, количество миграций,
mobile receipts и сохранённые unknown effects.

Обычный Doctor после переноса действительно выполнил `doctor.check_system`:
Core/PG/Redis checks healthy, private deletion restore guard healthy. Общий
Doctor verdict может оставаться unknown из-за неизмеренного качества/семантики;
это не заменяется HTTP200. Сервисы имеют bounded JSON logs и healthchecks;
mobile ingress/proxy дополнительно проверяются по HTTP/actual receipt.
Ресурсы нового стенда и сборок находятся на `/srv/storage`. Загруженный только
для сборки Go image сохранён там в tar и удалён из root-backed Docker store;
свободное место `/` возвращено к исходным приблизительно2,8GiB. Чужие images/
containers/cache не удалялись. Корневой раздел по-прежнему заполнен на99%.

## Ограничения сравнения и откат

[Живое сравнение](../ai/tool-discovery-native-20261019.md): одна полностью
измеренная пара дала15,54% меньше полного native token usage и2,14x больше
задержку. Preliminary quality eager4/4, deferred3/4; неухудшение качества
не доказано. Денежная полная стоимость и часть исторического usage неизвестны.
Включение этого opt-in по запросу владельца не является общим release verdict.

Для отката сначала остановите приём/обработку, сделайте новый dump текущей БД
и **после него** сохраните самый свежий независимый deletion anchor/ключи.
Не восстанавливайте старый backup поверх новых receipts и не запускайте старый
primary параллельно. Отмена discovery требует согласованного false на Core и
Broker; сохранённые journals/effects/budgets остаются. Смена адреса телефона
назад требует той же остановки listener и проверки сохранности очереди/token.
