# Prospective fresh pilot: independent methodological proposal

Status: proposal only. This document authorizes no native collection and creates
no replacement evidence for A/B/C. No v2 expectation or semantic judgment is
disclosed here. The frozen v2 mechanical scorer and acceptance rubric are intact.

## Independent experiment, retained history

A new complete experiment can be credible after a specifically diagnosed fixture
defect is repaired and independently tested. It must use newly authored hidden
episodes, not renamed or reworded reruns of any previously started episode.
All24 episodes,12 positive/negative families and96 planned owner opportunities
must be declared before any new native response. Both arms receive the same new
fixture/protocol. Keep the exact frozen candidate instruction and acceptance
thresholds. Freeze a new masked mapping, schedule and all file commitments before
admission. Neither arm may be selected or removed based on observed quality.

A/B/C remain a separate incomplete prior experiment, with all174 admissions,
known token usage and2 unavailable-usage attempts. Do not combine a fresh
experiment's observations with old controls to fabricate a completed old matrix.
Report the new experiment, prior failures and cumulative accounting together.
Predeclare finite new per-run/turn/window allowances and its own absolute wall
deadline. A new deadline belongs only to the genuinely new experiment; it does
not reopen or extend any prior task/mandate/window.

Fresh controls should be authored only after the public interface, source and
fault policy are fixed. The independent verifier may review fixture changes,
but must not receive old arm mapping or tune the candidate using hidden results.
The new set must preserve scenario difficulty and all authority, provenance,
completion and effect criteria; it cannot remove lifecycle seams that exposed a
fixture limitation. New concrete cases should differ in their actual problem
structure, resources, constraints and event order, not merely identifiers.

## Required zero-native gates before fresh controls execute

1. **Root cause and repair.** Reproduce the original defect in an isolated clone,
   record the exact failing operation with fixed safe phase/class diagnostics,
   and demonstrate why the fix addresses it. Original C bytes, schemas, task
   budgets and deletion anchors remain untouched. A clone of PG alone must not
   be described as restoration of a missing filesystem deletion anchor.

2. **Store and schema fidelity.** Verify required original primary/unique keys,
   constraints, post-data objects and schema/search_path isolation. Confirm
   source deletion manifests are initialized only for fresh fixtures and retained
   unchanged across a fixture restart. Verify each reconstructed repository uses
   the same business and reserved authority readers. Do not read auth values.

3. **Actual turn preparation, beyond seed/apply/snapshot.** Exercise the real
   `evaluate` preparation, `enrichWorking`, source/Catalog/profile bundle builder,
   formatter, mandate lookup and ordinary Input/Core preparation after every
   public lifecycle event and restart. A scripted offline provider is sufficient
   for this gate and must be labelled a structural stub, never language evidence.
   It must observe actual assembled requests; replacing production memory with a
   fabricated bundle is not acceptable. The earlier setup-only preflight passed
   all24 controls yet could not exercise C's later pre-input failure.

4. **Lifecycle combinations.** Public regression fixtures must cover accepted
   preference correction/replacement/revocation/deletion, user and session scope,
   source revision and access changes, stale pins, restart, inactive task and
   typed task amendments. Run a full subsequent preparation, not only the event
   API. Distinguish declared expected admission denial from infrastructure or
   observer failure. Currentness failure cannot be repaired by dropping source
   checks, copying accepted profile bytes into Working Memory, admitting stale
   history or granting a wider mandate.

5. **Effect and completion fidelity.** Existing public tests retain real Broker
   authorization, GET+prepare, confirmed POST/idempotent receipt and independent
   body/version/hash/count, stale CAS, foreign-object and true read-only denial.
   Confirmed effects, unsuccessful proposals, unknown effects, run finals and
   owner verification stay separate. Actual queued automatic continuations and
   later owner inputs must retain FIFO and per-task revision/mandate identity.

6. **Terminalization and fault injection.** Test the proposed failure policy
   through the ordinary worker/kernel with offline fault streams, not a hand-set
   run/input status. Cover an error before text, after partial text, after a prior
   confirmed tool effect, after a tool proposal, after an apparent final, auth
   failure, source/ownership observer failure and journal-finalization failure.
   Assert no retry/continue call for the failed slot; exact later owner input
   either proceeds safely under production ordering or stays explicitly blocked.

7. **Complete evidence and independent preflight.** Verify all required durable
   tables plus actual Input claim, session ownership/fence and retry checkpoint
   evidence. Every exported native attempt joins window/n -> run -> accepted
   input -> opportunity; every confirmed effect joins proposal/authorization/
   dispatch/receipt and independent object read. Source/context and nullable
   usage evidence must survive each injected failure. Then independently run
   fresh hidden setup and full-preparation preflights without native/auth calls.
   No expectation file enters the runner. Failures remain explicit; no case is
   silently skipped to admit the experiment.

All relevant public gates should pass against one committed producer under
local race checks before native admission. Candidate/hash, baseline/output
contract, actual serialized trusted instruction integrity, Broker/backend/hash,
source grants, model label, protocol, scorer and schedule are pinned together.

## Prospective response-stream protocol failure policy

A narrowly defined recorded failed turn with no retry can be followed by the
next original scheduled turn. A stage and error code alone do not establish this
boundary. Require all of the following before advancing:

- Exact immutable native journal identifies `response_stream` plus the fixed
  `provider_protocol_error` class; actual observed event order and partial bytes
  or their protected artifact references are preserved. There is no synthetic
  successful final and no parser fallback that converts partial text to a final.
- No tool proposal in the failing native entry, no ambiguous final/tool event,
  no in-flight dispatch and no unknown action effect anywhere in that slot.
  Confirmed effects from earlier native entries in the same slot remain durable,
  charged and visible to the next request. They are never repeated as recovery.
- The original Core/Input has reached a real terminal failed state, its claim and
  execution lease/fence are released or proved expired, the worker has stopped,
  no retry checkpoint can dispatch and no unfinished continuation can replay the
  failed attempt. Journal persistence and reserved usage reconciliation succeed;
  unavailable usage remains NULL/UNKNOWN. Missing evidence means global seal.
- The next step is exactly the next prospectively scheduled owner/event step,
  using the existing task, resource and source state and unchanged original
  deadlines/mandates. No reseed, repaired response, extra owner instruction,
  inserted model pass or synthetic task completion is permitted.

The ordinary Input implementation can leave an execution failure `blocked`,
which blocks later FIFO input. Therefore a collector must not simply clear a
seal and SQL-mark that input complete/failed. If the existing kernel finalizer
does not genuinely handle this case under current authority, the proposed
advance rule is not implemented and the window must stop. An offline test must
prove the real finalization and subsequent admission with no hidden replay.

Authentication/ownership/source-observer unavailability, incomplete/corrupt
journals, unexpected schema/fixture errors, ambiguous tool/action state, parent
deadline and any unclassified error still seal globally. An intentionally
declared inactive/revoked admission denial is scored as its actual boundary
outcome, not misclassified as observer infrastructure failure. The fault rule
must be applied identically to both masked arms, regardless of partial text.

## Missingness, comparison and closure

Predeclare separate counts: scheduled opportunities, actual admitted owner
inputs, actual runs, valid model finals, failed responses, unavailable responses,
confirmed/denied/unknown effects and cost telemetry. Reaching all96 scheduled
opportunities is not the same as obtaining96 usable behavioral observations.

Every failed or missing case remains in its original arm and family denominator.
Never use a complete-case comparison alone to claim superiority. Report paired
comparisons only where both observations exist, alongside all unavailable pairs
and the fixed full denominator. Do not reinterpret unavailable critical evidence
as no violation or PASS. Thresholds and promotion/closure gates are unchanged.
A failed turn may be retained as a failed observation while later original turns
provide additional evidence; it cannot supply evidence absent from that turn.

Even a complete fresh synthetic pilot cannot alone establish real-owner field
episodes, real external-tool qualification or deployment behavior. Check every
actual issue criterion separately; missing required evidence keeps #76 open.
