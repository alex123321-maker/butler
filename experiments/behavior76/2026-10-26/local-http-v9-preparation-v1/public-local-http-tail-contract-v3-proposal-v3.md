## Exact additional branch

Only a `client.Do` error with `resp == nil` and `ctx.Err() == nil` at the trusted capture point may generate the fixed safe reason `http_do_failed_without_response`, and only for an exact terminal typed socket/EOF allowlist: ECONNRESET, ECONNREFUSED, ECONNABORTED, EPIPE, ENETUNREACH, EHOSTUNREACH, io.EOF or io.ErrUnexpectedEOF. The classifier traverses at most 16 ordinary single-Unwrap links, rejects any multi-Unwrap error or unresolved/cyclic/deeper chain, and does not invoke arbitrary custom Is methods. At each link it rejects context.Canceled / context.DeadlineExceeded, every net.Error with Timeout()==true, and explicit TLS/x509 certificate-verification errors, even while the parent context remains live. Arbitrary/untyped errors, TLS certificate/authentication failures and HTTP client timeouts never acquire the local reason. No raw error-string inspection is permitted. The frozen source pin is the proof of this classification; the exported typed reason alone cannot reconstruct an unretained errno. A cancelled context, returned response (including response+error), dispatch/source/authority failure, response-body read error, EOF ambiguity, HTTP status, malformed stream, timeout, or unclassified error does not qualify. No raw error, endpoint, request, credential or response body is recorded. Later context/source/authority/observer/journal failures still have global priority.

This reason describes the client's observation. It does not prove the provider failed, received no request, performed no computation, or incurred zero expense; usage remains UNKNOWN.
