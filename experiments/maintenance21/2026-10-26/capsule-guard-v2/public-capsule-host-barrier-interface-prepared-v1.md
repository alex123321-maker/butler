# Minimal capsule host barrier interface — PREPARED_ONLY

This is an additive design proposal for the next fixed runner, not an implementation, formal source/corpus freeze, hidden authoring or execution admission. It reuses the private measured-host approach of measureBuildBounds but does not reuse the compiler's identity or numeric profile as proof of capsule isolation.

## Trusted construction

One private constructor pins the local Docker socket, fixed operator target/topology, exact GuardedImage with image/candidate/guard/package digests, guard executable identity, profile revision, current supported protocol and concrete finite resource/I/O/time limits. Request input cannot choose container names, image tags, command/entrypoint, host paths, mounts, network, Docker API fragments or credentials. The constructor uses distinct operator-owned keys/clients; a candidate never receives a Docker, controller or signing handle.

A small interface can have these conceptual operations; these are not model tools or public arbitrary RPCs:

1. `Prepare(ctx, expectedGuardedImage) -> PreparedCapsule`: creates only the code-owned isolated guard container and its private control surface. It may start the trusted pinned guard waiting for its marker, but no candidate instruction runs and the currently deployed target is untouched. Record exact IDs and finite guard wait expiry. Unexpected/lost creation state is a failed operation with retained uncertainty, not an automatic second creation.
2. `Measure(ctx, prepared) -> BoundsWitness`: resolves the actual running guard PID and physical state, validates all expected identities/limits below and returns a typed bounded witness with exact profile/image/guard/candidate/runtime/container/PID/start-time identity and observation time. Unsupported/hidden/mismatched physical state denies publication. It exports no raw host environment, sockets, keys or arbitrary file contents.
3. `AdmitAndPublish(ctx, prepared, exactSignedClaim) -> LaunchReceipt`: holds the node's exclusive target/effect fence, validates original controller signature and exact target/base/candidate/profile/fence/expiry, obtains one-use live NodeControl dispatch, rechecks owned process/witness identity and live deadline, then exclusively/atomically publishes only the fixed marker. Marker claim hash equals the exact verified raw claim; candidate hash equals measured image member. It never accepts a caller-selected marker path/body or an unsigned marker as permission. No PG transaction spans Docker/IPC work. The exact dispatch/physical-effect linearization and owner-stop race must be declared; an already admitted effect remains completed/UNKNOWN rather than falsely denied when a later stop wins.
4. `WaitAndObserve(ctx, launch) -> RuntimeEvidence`: imposes the original bounded runtime deadline and bounded stdout/stderr/result protocol, captures actual process/functional observations, then stops/joins the whole owned runtime when required. It preserves original cause, exact first stop and any late physical outcome. Healthy process exit and task/effect success remain separate.
5. `Close(ctx, prepared) -> CleanupReceipt`: touches only exact owned objects, records actual join/deletion status and retained image/artifact IDs. Failure is visible and cannot produce a qualified run. A lost response is not silently retried into another effect or reset to success. Any permitted idempotent cleanup must be separately specified, with no broad Docker/host pruning.

Keep these operations unexported or behind a fixed operator-only boundary. They do not expose a general run/exec/sign/mount/inspect-path function. The independent checker, not the capsule, interprets RuntimeEvidence and signs its own full review through the frozen fixed/hidden functional checks.

## Actual physical witness

- **Identity:** actual Docker container ID/image ID/configuration; code-owned entrypoint `/maintenance-guard`, no author-selected command override/environment, and an explicit fixed allowance for harmless daemon defaults if present; actual `/proc/<pid>/exe` guard identity; PID start time plus matching container/cgroup membership. Repeat identity/freshness at publication so a restarted/replaced process cannot inherit a stale measurement. After exec the candidate identity and exact `GOMAXPROCS=2` environment are separately observed; the guard witness is not a functional candidate result.
- **Privileges:** actual UID/GID, effective/permitted/inheritable/ambient/bounding capability sets consistent with the fixed no-capability profile, no-new-privileges and no privileged/user-host namespace mode. The cgroup belongs to this exact container and has no candidate-writeable control surface.
- **Resources:** actual cgroup-v2 memory, CPU, PIDs and effective no-swap at the worker or an ancestor, using concrete frozen capsule limits. measureBuildBounds currently hardcodes compiler image,1GiB/128PIDs/oneCPU; it cannot be renamed or copied unchanged as a128MiB/32PID capsule proof. The host and guard output buffers/hashing memory count toward the actual process limits.
- **Filesystem/FDs:** actual read-only root, exact candidate and guard hashes/modes, no mutable mount over them/ancestors; no arbitrary host root, Docker socket, credentials or PG mount. A private marker view must be host-write-only and candidate-nonwritable (for example a code-owned read-only mounted control view with host atomic publication). Avoid mounting an author-writable directory. Only the declared bounded data/output scratch and intended stdin/stdout/stderr are present; no inherited signing/socket FDs or host environment are passed.
- **Network:** actual isolated network namespace and no external routes/interfaces/capabilities or socket mounts granting network access. Existing compiler probe checks Docker NetworkMode plus IPv4 route text; that alone is not an independent IPv6 or arbitrary-socket egress proof. The candidate does not contact controller/PG/Broker; a trusted fixed adapter outside the capsule handles ordinary Core/Broker admission and bounded capsule I/O.
- **Timing/failure:** finite prepare/measurement/guard/runtime/output/cleanup deadlines, derived from the trusted plan and current context; no timeout increase or retry follows a failure. No launch when authority, source, compatibility, identity or witness becomes unavailable. Keep missing measurements explicitly unqualified.

## Required evidence before claiming this interface works

Retain actual guarded pre-marker execution with candidate absent; measured physical witness tied to the real container/PID; exact current signed dispatch and marker; actual candidate process/exit/output identity; real original-task function through Broker; owner stop/currentness; complete runtime join and cleanup evidence. Existing cold-image checks and synthetic PID14351 process replacement are useful prerequisites, not substitutes. Full release acceptance additionally requires the prior functional-contract's actual pending approval/continuation, independent signer, trial/promotion/rollback and incompatible-state denial observations.

The numeric capsule profile, data protocol and deployment switch remain choices for the public implementation contract before a formal freeze. This note creates no new hidden cases or fault tests and raises none of the existing limits.
