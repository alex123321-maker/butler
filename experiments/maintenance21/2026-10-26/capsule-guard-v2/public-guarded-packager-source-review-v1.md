No concrete command/entrypoint injection, candidate execution path or new admission bypass was found in the reviewed packager. Guard bytes are private operator configuration, copied at construction, checked against a lowercase digest and static amd64 ELF structure. The candidate reuses executableArchive/builtELF validation; compiler and module identity are checked at Package. The guarded archive is code-created in fixed candidate/guard order with exactly two regular files, uid/gid65532 and0555 modes; no candidate Dockerfile/path selects packaging. Guard identity is included in PackagingSHA256 separately from the candidate and image identities.

Image import verifies actual immutable image ID and exact entrypoint `/maintenance-guard`, user, workdir and absence of image Env/Cmd/Volumes. Actual file bytes/modes are then read through a never-started, disposable container. The tar readback verifies exact regular member name, uid/gid/mode, bounded full bytes/hash, no link and no next tar member. It is a file-member check, not a claim that arbitrary bytes after a tar end marker constitute a different Docker filesystem member or a complete adversarial-daemon attestation. The private Docker daemon remains a trusted host component.

Cleanup is correctly deferred after a valid container ID is known and uses its own five-second background context; a failed DELETE suppresses success by replacing the named result/error with ErrBuild. It does not stop/kill arbitrary processes or delete arbitrary host paths. A response lost before the created container ID is recovered can leave a cold container, and a later failed verification can leave the imported image. These are explicit failed operations/possible retained artifacts, not evidence of successful cleanup; future operational inventory should retain known IDs and unknown creation status rather than claim zero residual objects. No automatic broad/pruning cleanup is requested.

The legacy scratch recipe string and executableArchive validation are unchanged. Its refactored helper still selects `/candidate`, emits equivalent JSON entrypoint bytes and applies the old actual image configuration checks. The new helper permits only the two code-owned entrypoints, bounded archive bytes and an independent30s import/inspect context. The existing legacy actual-build case passed in the retained new log.
