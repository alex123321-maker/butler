# Новый оценщик и набор полезности памяти: проверка без модели

На laba проверен коммит `c0d6d47ccf73005ad0e07168be998564bd8ecf87`.
**38 основных тестов прошли, 0 ошибок, 0 пропусков**, включая прежние проверки
memory acceptance и 12 новых `TestMemoryUtility*`; с подтестами — 103 pass-события.
Race detector, vet обоих пакетов, сборка CLI и создание нового приватного набора
завершены с exit0. Контейнер — `--network none`, Go1.27.2, один CPU, 2GiB.
Это проверка измерительного инструмента, **не результат нового A/B/C**.

## Реализовано

- Отдельный перспективный Go-оценщик: строгий JSON, точный факт и доказательства,
  независимые от финала наблюдения эффекта/проверки/неизменности оригинала.
  Подстрока с ID артефакта и слово UNKNOWN больше не являются достаточным
  условием в этом новом протоколе. Старый frozen scorer не менялся.
- Корректный подтверждённый отрицательный ответ проходит. UNKNOWN, отсутствие
  эффекта без подтверждённой причины, неверная проверка, старый артефакт,
  лишняя подготовка, несовпавшие источники и неполные наблюдения отклоняются.
- 24 случая: прошлый факт, исключение из предпочтения, продолжение задачи,
  повторное использование процедуры; в каждой семье полезность, устаревание,
  отзыв, отвлекающие источники и достаточность текущих данных. Дополнительно
  четыре регрессионных oracle для состояния/эффекта/артефакта.
- Прежний источник перед удалением сохраняется в приватном preparation отдельно
  от текущего tombstone. Это позволяет следующему сборщику проверять реальный
  жизненный цикл источника, а не его отсутствие с самого начала.
- A может восстановить процедуру из трёх текущих документов; B/C могут использовать
  допустимый прежний рецепт. Текущие данные не спрятаны ради победы памяти.
  Для исторического факта честный отказ A отмечается отдельно от выполнения задачи.
- Диагностика разделяет допустимость evidence, релевантного кандидата, открытие
  и применение. Нерелевантная разрешённая ссылка не подтверждает правильную догадку.
- Учёт сохраняет failed/unknown usage и расходы подготовки; дубли ID, отрицательные
  токены и переполнение отклоняются. Полнота реального журнала будет проверяться
  сборщиком; helper не выдаётся за такую проверку.

## Проверка и сохранность

Источники на laba сверены с 6723 Git blobs. Единственная нормализация — объявленный
`.gitattributes` CRLF для `verify-changed.ps1`; после неё несовпадений нет. Первая
проверка без этой нормализации сохранена отдельно, а не переписана.

Артефакты: [машинный итог](verification-summary.json), [лог](build.log).
Полный test JSON, бинарник и приватный набор находятся в
`/srv/gitea/butler-acceptance/issue115-memory-utility-20261029-v2/reports`.
Все хеши приведены в машинном итоге. Эталонные ответы и исходники подготовки не
публикуются в Git; наружу сохранены только commitment и число случаев. Публичные
шаблоны и проверка автором не являются независимым скрытым контролем.

Первый более широкий запуск на промежуточной версии находится в отдельном
`issue115-memory-utility-20261029-v1`; его результаты не подменяют проверку
финального коммита. В нём [146 основных тестов прошли](intermediate-broad-check.json),
ошибок нет; `TestNativeCommunicationRetainedContentReviews` пропущен, поэтому
этот запуск не является проверкой его native-данных. Прежние окна native v1–v6, неудачные попытки и их расходы
не открывались для изменения. **Новых обращений к модели — 0.**

## Что ещё не выполнено

CLI не подключён к реальному сборщику Core/Broker: источник записывается и
читается пока в контрольных данных, а не новым прогоном Butler. Нужны адаптер
оригинальных receipts/журнала, фактическая подготовка и отзыв источников, реальный
поиск/загрузка навыка, отдельный typed-rejection recipient и независимая проверка
набора до выводов о качестве. Свободный текст требует отдельной семантической
оценки; новый scorer его не интерпретирует и старые ответы не переквалифицирует.

Политика памяти рабочего Butler не изменена. #115 остаётся открытым.
[Протокол следующего исследования](../../../../docs/testing/issue115-memory-utility-v1.md)
фиксирует эти границы, сравнение A/B/C и отдельные диагностические варианты.
