# Исправление чтения памяти без новых обращений к модели

На `ssh laba` воспроизведён дефект применимости `memory.search` и исправлен порядок
отбора источников. Новых запросов к модели: **0**. Старые A/B/C-результаты,
неудачи, UNKNOWN и расходы не пересчитывались. Основной Butler не обновлялся.

## Что произошло

[Исходные восемь отказов](original-memory-failures.json) взяты из закрытых
`case-*-database.json`, без повторения старых запусков:

| Стадии | Отказ | Вывод |
| --- | --- | --- |
| 16,18,20,21,32,57 | `memory.search`, `effect_unknown` | Исправляемый дефект порядка отбора/закрепления уроков |
| 41 | `memory.search`, `execution_stopped` | `budget_external_calls_mandate`: корректный отказ до dispatch |
| 42 | `memory.open`, `execution_stopped` | Тот же исчерпанный бюджет; offset9000/max_chars1000 допустимы |

Поиск находил уроки из нескольких окружений и вызывал `Catalog.AccessTx`, который
закреплял их в `memory_run_sources`. Последующая проверка применимости отбрасывала
несовместимый урок из ответа, но его pin оставался. Финальная проверка lineage
корректно запрещала выпуск такого ответа. Наружу это выходило как неопределённый
результат отправленного инструмента. Неверная JSON-форма ответа, отсутствие
текста модели и превышение допустимого offset не были причиной этих шести сбоев.

## Изменение

Владеющий Orchestrator передаёт Reader текущий fingerprint окружения. Существующий
SQL-предикат применимости урока и его предков выполняется **до** лексического и
семантического отбора, пагинации, чтения тела и закрепления. При отсутствии
experience consumer уроки исключаются, обычные разрешённые данные остаются.
`open/neighbors` возвращают DATA `denied` для несовместимого урока до нового pin.

Полные Catalog/authority/privacy/currentness/dependency проверки и финальная
проверка остаются. Старые pins не удаляются: уже показанный несовместимый урок
по-прежнему запрещает выпуск. Бюджеты и модельные/tool контракты не расширялись.

## Воспроизведение и границы доказательства

Использованы шесть отдельных копий синтетических case-БД, без `system_settings`.
В них созданы новые диагностические session/task/run/lease/grants. Старые inputs
не возобновлялись. Исходная PG была включена только для выгрузки и затем остановлена.
Диагностическая PG не имеет сети/публичных портов; тестовые контейнеры используют
только её изолированное пространство сети. Auth mounts отсутствуют; Go modules
доступны из прежнего кэша при `GOPROXY=off`.

До исправления все шесть запросов воспроизводили несовместимый набор pins и отказ
`current memory access proof required`. После исправления метаданные применимы,
`BindExperienceLineageTx` успешен; возвращаются только совместимые элементы
(3,3,1,1,2,2). Это **не** полный повторный PASS старого окна: следующая полная
проверка в копиях продолжает запрещать старую reviewed extension с истёкшей
готовностью (`reviewed extension is unavailable`). Её срок не продлевался.

Отдельные свежие синтетические проверки проходят через настоящий процесс Broker
и владеющий read endpoint: обычные данные находятся, несовместимый open явно
отказан, лишних pins и `effect_unknown` нет. Совместимый урок читается; negative
feedback, смена окружения после реального чтения и источник с уроком-предком
сохраняют защиту. Новая регрессия воспроизводит старый порядок, проверяет limit1,
семантические кандидаты и сохранение ранее показанных pins. Scripted fixture
provider не вызывает внешнюю модель и не является доказательством её качества.
