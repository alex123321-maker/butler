# C43: исправление закрепления неприменимого опыта и разбор расходов

На laba воспроизведён и исправлен дефект кандидатов `memory.search` в C43.
Новых обращений к внешней модели: **0**. Старый C43 остаётся failed, его NULL
attempt и все прежние результаты/расходы сохранены. Новое A/B/C не проводилось;
#115 остаётся OPEN/NO_GO, PR158 — draft, рабочее развёртывание не обновлялось.

## Подтверждённая причина C43

Текущая задача разрешала проверку прежнего UNKNOWN, запрещая новую подготовку.
В записанном scoped Broker catalog нет `extension.project.prepare-patch`.
Урок `source_713357db52ad7c692b9195f45f003878a6b40942` относится к тому же
environment, но зависит одновременно от inspect и prepare-patch.

Прежний предварительный фильтр проверял environment/claim/feedback, пропуская
такого кандидата. Catalog успевал закрепить его полную цепочку; затем полная
проверка применимости скрывала текст. Поиск возвращал `empty`, но источник
оставался закреплён за run. `CheckPinnedTx` проверяет установленную версию;
следующая полная проверка `CheckPinned` дополнительно требует текущие разрешённые
Broker contracts и закономерно отказывает. Это не истечение двухсекундного
лимита: записанный отказ занял183860µs, базовый Catalog прошёл, пул был свободен.
Durable run содержит `transport_error` / `memory_source_stale`; ExecutionResult
отсутствует. До этого завершились skills.search, HTTP503, inspect и memory.search.
Загрузки skill в C43 не было. См. [точные метаданные](c43-proof.json).

Исправление передаёт уже подготовленный вне SQL снимок разрешённых Broker
tool/hash/revision в Reader. До ранжирования, страницы и Catalog pin проверяются
зависимости всех lesson ancestors. То же правило действует для semantic candidates
и exact open/neighbors. Обычные разрешённые данные остаются доступны. Никаких
дополнительных полномочий, удаления уже раскрытых pins, ослабления source guard,
продления timeout или миграции схемы нет. Повторные полные проверки сохранены.

## Воспроизведение и проверка

Из остановленного частного PG скопирована только синтетическая C43 DB через
pg_dump с исключённой `public.system_settings`. Исходный PG снова остановлен.
Отдельный PG `issue115-c43-pg-20261029-v1` имеет network=none, без host ports и
provider auth. Все Go-проверки выполнялись на laba с offline module cache,
Go1.27.2, настоящим PostgreSQL/pgvector; новый сетевой доступ к модели невозможен.

- [Replay сохранённых данных](retained-replay.log), [его исходник](retained-replay.go.txt):
  свежие временные session/task/run/lease/grants, все мутации rollback.
  До исправления: `empty`,1 неприменимый lesson pin. После: `empty`,0 таких pins,
  текущая локальная проверка проходит. Старые запуски не возобновлялись.
- Старый installation expiry в копии сохранён. Первая диагностическая проверка
  ошибочно ожидала здоровую позднюю проверку старой установки и получила
  `reviewed extension is unavailable`. После уточнения assertions доступ не
  продлевался. Replay проверяет чтение/lineage, а не завершение исторического run.
- Свежая PG-регрессия отдельно доказывает точную причинность: старый порядок
  возвращает empty с pin; базовые sources и исходные зависимости проходят,
  текущий набор инструментов запрещает продолжение. Missing/changed contracts
  фильтруются, compatible проходит; descendants, exact open/neighbors и semantic
  candidates проверены. [Итоговый race/vet](final-v4.log).
- [PG reader/experience и actual Broker](validation-v2.log): race-прогоны,
  текущие исправления/удаления/feedback/права, положительное чтение и missing-tool
  dispatch. Broker test действительно запускает приложение Tool Broker;
  in-process controlled notes fixtures не являются внешними обращениями к модели.
- Первый wrapper без Broker binary пропустил интеграцию и не принят за приёмку:
  [сохранённый журнал](rejected-missing-broker-wrapper.log). V2 использовал binaries.
  Отдельный backup test в общем package-прогоне потребовал внешнюю процедуру;
  затем выполнены реальные seed → pg_dump → delete → pg_restore → restore,
  все3 фазы прошли с `-race`: [seed](backup-seed.log), [delete](backup-delete.log),
  [restore](backup-restore.log). SKIP не засчитан за PASS.

## Почему этот вариант памяти обходится дороже

Ниже прежние48 контролей, по16 на arm. Строгая оценка задач не пересматривалась.
Tokens — известные полные provider totals, включая thinking; денежная стоимость
не установлена. [Пересчитываемые трассы](abc-trace-attribution.json),
[read-only скрипт](abc-analysis.py).

| Вариант | Подтверждённые задачи | Вызовы в контролях | Tokens контролей | Tokens с нужной подготовкой |
| --- | ---: | ---: | ---: | ---: |
| A без опыта |14/16|55|389172|482514|
| B одинаковые notes |14/16|101|1339684|1460558|
| C notes + skills/guidance |13/16|100|1026481|1329435|

1. Основная прибавка — один сложный known-failed сценарий, control-03 в двух
   повторах. A потратил4 вызова/25115tokens; B —48/908623; C —28/403436.
   Разница B−A здесь883508tokens:92.95% прибавки контролей или90.33% прибавки
   полного arm с подготовкой. В B18 исчерпаны24 model turns; B42 завершился с
   честной неопределённостью, но критерий доказанного unsupported не выполнен.
2. B добавил23 поиска и24 открытия; C —15 поисков,11 открытий,14 skills.search,
   6 loads. В B23 из24 opens запрошены страницами по1000 символов. Один и тот же
   источник читался до8 раз с разными/перекрывающимися offsets. У B42 вход модели
   вырос с5770 до40763tokens.96.50% прибавки control tokens B−A — входные tokens.
   Это свидетельства разрастания контекста и числа шагов. Точных одинаковых
   search/open вызовов не найдено: «цикл чтения» не означает буквальный повтор args.
   Resume-запись содержит новый tool result; полного HTTP replay/оценки повторно
   переданных bytes здесь нет.
3. Память не содержала подтверждённого ответа на главный спорный вопрос.
   У original03 вердикт UNKNOWN: effect_absent после reconciliation не доказывает,
   принимает ли проект `ready=maybe`. Урок это прямо сохраняет. Поиск не может
   превратить такую запись в доказанный отрицательный опыт. Дополнительное чтение
   не добавляет отсутствующего факта. [Проверка текста и размеров](lesson-presentation-audit.json).
4. Простые положительные задачи A уже решал. Четыре целевые загрузки
   C на repeat/similar не добавили подтверждённых задач. Ещё две загрузки были
   в known-failed сценарии. Skill4804chars описывает общую подготовку readiness
   patch; его when/not_applicable не кодируют доказанный отказ `ready=maybe`.
   Это правдоподобное объяснение слишком широкого выбора, а не причинный A/B-тест.
   Исправление C43 не решает выбор/остановку чтения в C03.
5. В остальных14 контролях тоже есть overhead: A364057tokens, B431061 (+18.4%),
   C623045 (+71.1%). Подготовка всего нового набора отдельно стоит302954tokens.
   Эти arm totals включают полную необходимую подготовку для каждого arm и не
   являются разделением уникального общего расхода.

Предположение, что полезный текст спрятан за большим Observation, **опровергнуто**:
model_notes начинаются на позиции38, раньше observation; сами notes999–1317chars,
целые lessons5446–12015chars. Однако короткие opens действительно приводили к
множеству чтений исходных доказательств.

C43 объясняет дополнительный неуспех C техническим дефектом до загрузки навыка;
считать его доказательством плохого рассуждения модели с навыком нельзя. В C16
осталась отдельная некорректная neighbors proposal; неподдержанные prepare всё ещё
давали UNKNOWN. Нельзя задним числом назначить C43 успех или убрать его расход.
Два повтора узкого синтетического корпуса не доказывают, что память всегда вредна.

Дальше обоснованы ограничение бесплодного поиска по уже неизвестному исходу,
компактное представление нужных доказательств и проверяемое правило прекращения
дальнейших чтений при отсутствии новых фактов. Простое повышение потолков
увеличивает возможную стоимость. Эффективность таких изменений потребует нового
отдельного исследования; в этой задаче они не внедрялись и модель не вызывалась.
