## Что уже показывает реальный корпус

У всех 92 элементов Strawberry Unicode равен `🌟`. У 47 из 48 AIActions —
`🙂`. Эти метаданные не различают реальные объекты: пирог, клубнику, бант,
поиск документа или настройки. Это конкретная иллюстрация потери информации,
а не доказанное улучшение nDCG от captioning.

83 просмотренных статических изображения преимущественно изображают клубничные
десерты и напитки; один элемент — бант. Три пары содержат один и тот же
фотографический объект с небольшими отличиями кадрирования/масштаба.
Эта подборка даёт пищевые примеры, но не подтверждает разнообразие ингредиентов
вроде сыра, помидора и таймера для виджетов.

В анимациях есть существенная неоднозначность: сложенные ладони допускают
«просьба/спасибо/молитва», выражения меняются по кадрам, перечёркнутый ноль
не всегда отличим от Ø. Разметка отделяет наблюдаемые признаки от возможных
смыслов и допускает null. Неуверенная идентификация механизма была исправлена
до модельных ответов; прежняя версия сохранена в PostgreSQL.

AI-разметка сделана по контактным листам с пронумерованными кадрами. Непрерывное
проигрывание всех оригинальных анимаций не проверялось. Разметчик — текущий
Codex, а не независимый человек. Это development-данные, не gold test set.
Простой Go-поиск по этой разметке находит по «отказ» кота с табличкой NO;
поиск не понимает отрицания, не выполняет stemming и не имеет калиброванного
порога abstention. Запросы после разметки не являются независимым тестом.

## Ресурсы и модельная часть

На старте: RTX 3060 Laptop, 6144 MiB VRAM, около 14 GiB системной RAM,
11 GiB доступно, 41 GiB свободного диска. Другие рабочие контейнеры сохранены.
GPU более высокого класса у владельца нет; разрешён ограниченный вариант на
имеющемся оборудовании или AI-разметка.

Основная V1/V2/V3 BF16-матрица из issue не выполнялась. Для доступной GPU
подготовлен отдельный Qwen3-VL-4B NF4 double-quant пилот, BF16 compute,
batch 1, 224×224, до 512 output tokens. Это изменение конфигурации отмечается
явно и не подменяет сравнение BF16. Gemma остаётся gated; её условия доступа
не принимались, веса не скачивались. Qwen8B также не скачивался.

Ревизии и дополнительные зависимости закреплены в
[pins.json](pins.json). ML image:
`sha256:1f8334477430a5d885a9defcbe79ac21367591dbe85f8f9ede4d4b50e45ff502`.
Go image:
`sha256:5cf287a799e6b94384bad13d16b14904c531f51ba65792237e122ce42b392f61`.
PostgreSQL image:
`sha256:ac08538c6f8b9904c33c8224c5e5706dbe760aca29db1d096972b4052c22a75d`.

Загрузка весов использует существующий приватный proxy reference Telegram;
провайдерские credentials не читаются. Стандартная загрузка была явно остановлена
из-за скорости и заменена ограниченной докачкой диапазонов с полным SHA256.
Exit137 остановленного preparation-контейнера — операторский stop, не доказанный
OOM. Веса, токены, исходные изображения и кадры не добавлены в Git.

Веса 4B (8 875 719 344 байт) докачаны и проверены по полным LFS SHA256.
Выполнено ровно 90 vision-вызовов, скрытых retry/repair нет. Все 90 имеют
сохранённый исходный ответ; inference exceptions и OOM — 0. Четыре конфигурации
сохраняются раздельно; это версии prompt одной NF4-модели, не V1/V2/V3 из issue.

V1 часто выдаёт английские значения; среди 59 разобранных JSON у 13 весь observed
пуст. Наличие кириллицы отмечено лишь в 5/60 ответов; это простой счётчик, не
оценка правильности русского языка. Стиль заполнен в одном ответе, possible_meanings
также в одном. У ru-v2 частая ошибка — inferred внутри observed/незакрытый JSON.
Ru-v3 даёт больше содержательных русских значений, но два ответа зацикливаются
до 512 tokens, ещё один имеет некорректную структуру. Первый проход не исправлялся.
Ни одна конфигурация не достигла предложенного порога schema validity 98%.

Ru-v3 одновременно сокращает/уточняет инструкцию и перемещает её после изображений,
а метки времени переводит на русский. Причину изменения качества по отдельности
из этих данных установить нельзя. Prompt менялся только на development.

Для парных первых шести элементов ru-v3 валидны 5/6 ответов в обоих режимах,
но ошибочные элементы различаются. Средняя latency: 8.17 s для восьми кадров
и 5.49 s для одного. Это шесть примеров, без независимой оценки динамики:
преимущество multi-frame по качеству не установлено. Фактические visual tokens
512 против64; image grids каждого 224×224 изображения — [1,16,16].
Входные токены:800/v1,1102/v2,961/v3-multi,380/v3-single.
Всего input75 036, output15 420 tokens.

Время первой выдачи p50/p95: v1 0.545/0.550 s, v2 0.651/1.080 s,
v3-multi 0.614/1.051 s, v3-single 0.248/0.983 s. Загрузка модели
3.92–15.15 s при разном состоянии файлового кеша; это не сопоставимые cold starts.
Peak process RSS по конфигурациям:7891.1/9014.6/9406.8/9439.3 MiB.
RSS включает отображённые файловые страницы и не равен cgroup memory charge;
контейнеры ограничивались8 GiB RAM без swap. Пик всей RAM хоста не измерен.
Общий максимум torch-reserved VRAM3158 MiB; это не полная память устройства.
GPU был свободен перед каждой загрузкой; зафиксированной конкуренции не было.

Неблокирующее предупреждение torch об отсутствии директории kernel cache
сохранилось во всех прогонах; JIT kernel caching отключён. Общий runtime не менялся.

Прогноз, НЕ новый benchmark: для100 элементов при v1 mean7.48 s потребуется
около12.5 min inference, при ru-v3-multi mean10.94 s —18.2 min, плюс загрузка.
Для оставшихся390 элементов ru-v3 это около71.1 min, но такой прогон не запущен:
наблюдаемое качество не оправдывает массовую генерацию текущим prompt.
По текущему корпусу100 файлов — около53 s импорта и22 s суммарного decode
wall time дочерних процессов; состав другого пака может изменить всё это.
Перенос этих скоростей на BF16/8B/Gemma не допускается.
Человеческий труд не измерен: людей-оценщиков0; исходные20–40 h из issue
остаются плановым ориентиром, не фактической стоимостью.

Платные API и аренда GPU не использовались. Стоимость электричества не измерена;
использование уже имеющегося оборудования не объявляется бесплатным.

## Проверки и ограничения

Пройдены целевые Go-тесты Telegram client, proxy/host/path/file guards и русского
лексического поиска; go vet для изменённых Go-пакетов; Python-тест строгой схемы.
Реальные импорт/декодирование/сохранность PostgreSQL проверены на laba.
Установка и запуск новых production-сервисов, отправка сообщений, чтение
переписки и getUpdates отсутствуют.

Подключение Codex Browser не удалось: runtime ссылается на отсутствующий
browser-service.mjs. Поэтому именно установленные в аккаунте пользователя паки
и ответы бота через открытый Telegram пока не проверены. Импортированы публичные
паки из issue; это не список установленных пользовательских паков.

Остаются: проверка WEBM, окончательные квоты и near-duplicate groups, immutable
test split, независимые queries/qrels, полноценные V1/V2/V3 и single/multi-frame
сравнения, EmbeddingGemma2/R0–R4, калибровка abstention, CI, повторяемость,
слепая оценка, widget evaluation. Рекомендация production rollout не дана.
Вывод этапа: **resource go для 4B NF4 на laba; quality no-go для массового
captioning текущими prompt; need-more-data для retrieval и production**.
Практический следующий этап на имеющемся оборудовании — доработка компактного
контракта/ограниченной генерации на development и расширение проверяемого слоя
AI-разметки с независимой оценкой; полный batch пока не рекомендуется.

Отдельные ограничения по задачам:
- Предметы: ручная AI-разметка даёт полезные поисковые признаки, но модель иногда
  ограничивается общим «иконка»; точность объектов независимо не измерена.
- Эмоции: допустимые трактовки сохраняются как inferred; слова модели
  «с пирогами» в expression pilot-011 показывают, что valid JSON не равен смысловой
  корректности. Процент critical hallucination без слепой оценки не заявляется.
- Анимации: v3 зацикливается на повторах движений; восемь кадров не доказали
  преимущество на шести парных примерах.
- OCR: W распознан в pilot-041; в v1 text иногда является массивом вместо строки.
  Одного примера недостаточно для CER, recall или оценки выдуманных надписей.

Все критерии закрытия #140 пока не выполнены. Корпус и инструменты позволяют
продолжить работу без повторной загрузки и без более мощной GPU.
