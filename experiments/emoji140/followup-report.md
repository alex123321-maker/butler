# Issue #140 — Колобки и поиск на имеющемся оборудовании, 2026-10-23

Продолжение [первого этапа](report.md), после разрешения пользователя использовать
имеющуюся машину и собственную разметку. Большая BF16-матрица не подменяется этим
экспериментом. Результат рассчитан на выбор следующего этапа, а не на включение
автоматического оформления в production.

**Вывод:** имеющейся laba достаточно для EmbeddingGemma2 BF16 text+image:
6870 кадров и648 текстовых входов обработаны за977.94s, peak torch-reserved
1368MiB, peak process RSS2097MiB. На Колобках R2_AI нашёл подходящий результат
в top5 для20/20 положительных запросов, прямой R4_light — для19/20.
Однако перенос abstention дал1/5 false accepts у обоих, при positive coverage
18/20 и12/20 соответственно. Это single-AI эксперимент, не production-приёмка.
Рекомендация: использовать проверяемые аннотации с ручным выбором кандидата;
прямой поиск оставить дополнительным способом поиска. Автоматический выбор и
отправку не включать. Смешивание lexical+dense через текущий RRF не улучшило
результат; усложнение pipeline этими данными не оправдано.

## Разметка и границы оценки

Дополнительно просмотрены и вручную размечены307 элементов исходной выборки.
Итого502 AI-аннотации: исходные450 и отдельно52 Колобка. Наблюдаемые признаки
отделены от трактовок. Например, предмет у рта `kolobki-046` оставлен неоднозначным;
OCR `048` помечен как текст с намеренно искажённой орфографией. Восьми кадров
недостаточно для доказательства полной динамики; непрерывный просмотр не заявлен.

После визуальной проверки родственные контурные/залитые значки консервативно
сгруппированы вместе с ранее найденными тремя фотографическими парами. Получилось
73 development /90 calibration /287 test:13 родственников уже просмотренного
пилота исключены из теста. Это явное отклонение от60/90/300, а не переименование
287 элементов в300. Все83 Strawberry остаются вне development/calibration.
Полнота обнаружения близких дублей неизвестна; возможна избыточная группировка.

Зафиксированы120 русских запросов (20+10 calibration,70+20 test) и дополнительно
25 для Колобков (20 положительных,5 no-match). Запросы и входные файлы заморожены
хешами до просмотра выдач. Автор запросов и аннотаций — один и тот же AI.
**Это не независимый locked human test.** Пользователь разрешил саморазметку;
она не превращается от этого в двухэкспертную человеческую оценку из issue.
К моменту создания запросов автор уже видел результаты прежнего NF4-пилота;
независимость запросов от этих60 development-примеров также не заявляется.

Для исходных450 есть только известные положительные seeds. Поэтому Success@5 и
MRR@10 здесь означают попадание в известные релевантные seeds, а не исчерпывающую
оценку: неразмеченный правильный ответ может выглядеть ошибкой. Pooled nDCG и
полная recall для450 не заявляются. Для каждого из25 запросов к Колобкам явно
оценены все52 кандидата по0/1/2/3 (1300 AI-оценок); nDCG этого отдельного корпуса
можно вычислять, но независимости от автора аннотаций всё равно нет.

## Конфигурации

Одинаковая существующая EmbeddingGemma2, revision
`914f7f89142e33e77833254d9c9b90c3cef7303b`, BF16,768d, batch<=4,
max_seq_length2048. Загружены text+vision encoders, audio отключён.
Префиксы `SearchQuery`/`Document` используются только для текста;
изображения подаются без префикса. Фактический SHA256 весов записан в config.
Веса и существующий venv монтируются read-only, сеть и credentials отсутствуют.
Лимит контейнера8GiB без swap,2CPU; torch allocator ограничен75% VRAM.
Перед запуском GPU свободен; перед каждой encode-партией проверяется конкуренция.

| Система | Реально измеряемый вариант |
|---|---|
| R0 | Точный нормализованный token overlap по pack name и Telegram Unicode |
| R1_AI | Такой же lexical overlap по ручным AI-описаниям |
| R2_AI | Exact cosine по тем же AI-описаниям |
| R3_AI | Фиксированный RRF, k=60, полные lexical/dense ранги |
| R4_light / R4_dark | Прямые изображения: mean L2-нормированных векторов кадров, затем L2 normalization |

R1_AI/R2_AI/R3_AI нельзя называть результатами автоматического captioner.
Влияние индекса сравнивается при одних и тех же аннотациях; сравнения V1/V2/V3
captioner на одном embedder нет. R0 намеренно буквальный и слабый: без русских
CLDR-названий Unicode часто не имеет общих слов с русским запросом. Победа над
таким R0 сама по себе не доказывает пользу сложного production pipeline.
RRF при равных lexical scores использует детерминированный ID-порядок: это
возможный источник шума. После результатов правило не менялось.

Прямой поиск усредняет кадры и теряет их порядок; он не доказывает понимание
переходов эмоций. Светлый и тёмный фон сравниваются на одних и тех же кадрах.
Поиск exact; ANN/pgvector tuning отсутствует.450 и52 ранжируются раздельно;
неизменность исходного корпуса сохраняется.

Порог abstention выбирается только по30 исходным calibration-запросам:
допускается максимум1/10 false accepts, затем максимизируется positive coverage,
при равенстве выбирается меньше false accepts и больший порог. Для Колобков это
явно transfer-проверка, собственного calibration нет. В частности, шкала RRF
зависит от размера каталога, её перенос450→52 не квалифицирован.
Отчёт показывает сырые числители/знаменатели, Wilson-интервалы для долей и
2000 query-bootstrap resamples для средних/парных differences. Запросы разделяют
визуальные семейства; предположение об их независимости ограничивает CI.

## Ошибки и цена нового пака

На запрос про зелёную жвачку прямой поиск возвращает зелёное лицо с тошнотой
`kolobki-015`, а правильный `040` не попадает в top5. Пузырь появляется лишь в
конце просмотренных кадров; потеря временного порядка и усреднение — возможное
объяснение, не доказанная причина. На тёмном фоне дополнительно не прошёл запрос
про косящие глаза и язык. Семантическая пригодность тонких жестов всё ещё требует
ручной проверки. После обнаружения ошибок qrels и пороги не менялись.

Для R2_AI nDCG@10 на Колобках0.952, R4_light0.748; парная разница
R4_light−R2_AI −0.204, exploratory bootstrap95% [−0.299,−0.109]. Это сравнение
с тем же AI, который написал описания: оно не доказывает такое преимущество на
независимых пользовательских запросах. Для R4_light исходного корпуса0/20 false
accepts всё равно дают Wilson95% до16.1%; для Колобков1/5 — интервал3.6–62.4%.
Ни ноль ошибок, ни точечная оценка на пяти запросах не доказывают безопасность
порога. Отказ выбрать что-либо у R0 также не является успешным поиском: coverage0.

Фактическая добавка Колобков:52 файла,1 429 739 bytes, импорт20.52s,
сумма decode child wall time21.23s,416 кадров. Прямые embeddings:
57.56s на светлом фоне и59.96s на тёмном (без общей загрузки модели).
Прогноз для похожего100-элементного TGS-пака — около111–115s embeddings на один
фон, плюс импорт/декодирование/проверка; это линейная экстраполяция, не benchmark
другого пака. Время ручной AI-разметки отдельно не измерялось; людей-оценщиков0.
Новых generative captioning calls нет: их суммарно остаётся90 из первого этапа.

## Воспроизведение

Исходники: `prepare_followup.py`, `freeze_followup.py`, `prepare_kolobki.py`,
`freeze_retrieval.py`, `grade_kolobki.py`, `retrieve.py`, `score_retrieval.py`.
Файлы freeze создаются исключительно в новом месте (`open('x')`), предыдущая
версия не перезаписывается. `evidence/retrieval-input-lock.json` проверяется
runner перед загрузкой модели. Кадры и векторы хранятся в приватном `.cache`;
публичные manifests, config, метрики и top10 не содержат медиа/credentials.

```sh
# Из выделенной worktree на laba, после подготовки зафиксированных входов:
sh experiments/emoji140/run_retrieval.sh retrieval-NEW
python3 experiments/emoji140/score_retrieval.py .cache/research/retrieval-NEW
python3 -m unittest discover -s experiments/emoji140 -p 'test_*.py' -v
```

Для повторного расчёта score используйте новую копию выходных evidence, поскольку
результаты создаются без overwrite. Исследовательские данные остаются в отдельной
PostgreSQL; JSON и vectors — производные, production DB не используется.

## Оставшиеся критерии исходного исследования

Независимые человеческие оценки, полный слепой top10-pool для исходных450,
основная V1/V2/V3 BF16-матрица, надёжная оценка OCR/CER и factual hallucination,
WEBM, независимые widget previews и проверка временного порядка не выполнены.
Это конкретные ограничения отчёта, а не нулевые ошибки или успешно пройденные
критерии. До их устранения автоматический выбор/отправка emoji не рекомендованы.
Quality no-go первого captioning-пилота остаётся в силе; возможность запуска
4B NF4 на этой GPU уже подтверждена и не означает достаточное качество.
Issue #140 остаётся открытым; этот PR сохраняет воспроизводимые результаты
разрешённого эксперимента на имеющемся оборудовании.

Колобков. Core Go-код в продолжении не менялся; его целевые проверки зафиксированы
в отчёте первого этапа. Исходный primary checkout на laba сохранён.
